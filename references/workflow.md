作者：星迹。显示名为 星迹的AIGC，技术调用名为 `$cinematic-previz`。

## 每次调用前：确认独立模式或项目同步模式

有命令执行能力时，先执行本技能自身目录中的检查脚本。路径从本次实际安装位置解析，不使用作者电脑路径：

```powershell
python "<skill-dir>/scripts/sync_from_project.py"
```

普通下载用户没有 `.skill-source.json`，也未指定来源时，脚本返回 `status=current, mode=standalone`：使用当前完整技能包，不注册、不写文件、不联网，也不声称检查了远端最新版。安装到新目录或搬家后仍可使用。

已注册 `.skill-source.json`，或明确指定项目/来源环境变量时，按注册项目核对 SHA256 并同步。注册是维护者的可选功能，不是普通用户的安装前提；步骤见 [README](../README.md)。不要把当前工作目录自动当来源，也不猜远端分支。

- 必须得到 status=current 或 updated 才继续；updated 后重新读取返回的 skill_file 及当前任务需要的参考，不沿用之前加载的旧正文。若更新列表包含同步脚本自身，再运行一次确认 current；来源持续变化则停止并说明。
- LOCAL_CONFLICT/BUSY/来源缺失/其他错误时，不覆盖本地修改、不删活锁、不把旧副本当最新版。先报告具体路径和错误；在本次任务范围内解决来源或冲突后再检查。
- 已注册来源损坏或消失时不可降级成独立模式来绕过失败。独立模式也不删除活锁。当前宿主或用户 AGENTS 明确要求前置命令时，严格遵守，失败即停止。
- 没有命令/Python 能力且没有注册来源要求时，可用技能文本完成分镜、提示词和制作规划；明确未执行脚本检查。只有实际提帧、同步等功能才要求对应依赖，不能因此阻塞可独立完成的导演任务。
- 此调用前更新只从本机注册项目到安装副本，不把安装端修改反向写回，也不执行 git pull/push；`current`／`updated` 和 `remote_checked=false` 不证明 GitHub 已更新。要采用 GitHub 新提交，先在来源项目完成正常拉取/合并，再调用本 Skill。维护源码修改后另按 [维护更新收尾与 GitHub 备份](maintenance-release.md) 完成已有授权要求的上传及远端核验，不能用本机同步替代；无法检查远端时不能声称远端已是最新。
- “调用前”检查适用于每次新任务和同一聊天再次调用；不能因之前检查过而跳过。只读初始化同样先更新。

把剧本变成有理由的镜头，用Codex内置生图逐镜生成首帧白模预演；需要精确验证空间与运动时再用Blender，随后完成正式外观并按实际视频工具能力生成、衔接和剪辑。中文沟通；提示词语言遵循目标平台和用户偏好。

本 skill 已整合 DirectorSKILL 与 Scenario 两类预演的必要方法，不要求额外安装它们。来源和许可证见 [sources.md](sources.md)。

## 制作阶段与审核顺序

以下十步是制作主流程。新项目从第1步开始；已有项目核对已交付文件、版本和用户通过证据，从当前获准阶段接续，不重做已审核成果，也不恢复已暂停生产。只更新技能不等于授权执行这些生产步骤。

1. **优化或拆分为文档剧本**：先按下文[完整句边界](#剧本拆分的完整句边界)确定文本节点，再交传统剧本格式的可审阅文档文件，默认DOCX，用户指定其他格式时沿用。按场次写时地/内外景、人物、动作指导、对白、旁白/画外声、语气、表演及必要声音说明。保留用户原稿与修改版本；既有逐字旁白/对白未获改写授权时原样保留。文档不是Excel分镜、JSON摘要或平台执行词。
2. **用户审核文档**：交付实际文档，记录所审版本和明确通过/修改意见。未通过前停在文档修改，不制作Excel分镜或先行生图；时间经过、用户未回复或Agent自审不代表用户通过。
3. **制作Excel多列分镜**：仅在文档通过后，按[专业分镜规范](director.md#默认交付专业分镜表)制作核心主表，作为分镜、当前完整视频词和最终参考节点的单一交接入口；保留摄影、构图、表演、光影、声音、连续性及原稿到镜号映射。附表承载视觉场次基线、完整原稿、资产来源/专业物品词、规划历史和实际执行证据，不固定表数。JSON可作处理数据，不能替代Excel或绕过主表维护当前词。
4. **生成并映射资产**：依据已审核内容和用户上传的参考，生成所需人物、场景、表情、物品资产图；已有选中资产先核对复用。核心主表按镜号展示四类最终资产的实际图片、ID、选中版本、指纹和职责；同一资产可复用于多镜，各镜映射须明确。原图可从Excel导出或随包取得，交接不能只有本机绝对路径。确实不需要某类资产时标不适用及原因，不强凑素材。人物双参考与专业物品内容的原有核验规则继续有效。
5. **批量首帧入表**：资产准备后按同镜号制作首帧，逐张审图并将选中图片实际嵌入核心主表；保持文件、选图版本、指纹和提示词一致，不能只填路径或贴占位图。按项目已选的正式/白模类型执行，已有合格首帧复用；未要求时不自主生成规划尾帧，不为表格留了尾帧栏就补图。实际生成视频后的真实尾帧提取不属于规划尾帧生图。
6. **用户审核含首帧的Excel**：交付并核对实际保存的含图工作簿，记录用户对该版本的通过证据；意见涉及的镜头修订后更新对应审核状态。未通过前不进入平台视频制作，不能用Agent审图、图片目录或旧版表格通过来替代本次含图Excel审核。
7. **进入视频制作并上传素材**：含图Excel通过后，在既有预算与生成授权范围内接续；先把本轮所需全部图片资产、首帧和参考图上传到指定平台，音频参考按已选方案一并准备。记录真实平台资源ID、来源版本及就绪证据；accepted不冒称ready，已有素材核对复用，不重复上传。审核通过不推翻用户“仅草稿/不提交”等当前范围限制。
8. **创建并连接对应节点**：先检查完整句节点边界，再按句子节点与镜号的对应关系建立图像资产、参考与视频节点映射，并以真实边连接，核对图像/音频职责、模型及实际参数。核心主表同步参考顺序、可复用节点和依赖、真实平台资源/节点/边ID及状态、生成参数；尚未创建时保留稳定计划ID和“未创建”，不编造实站ID。用户要求可见参考节点连线时，不以视频节点内部上传代替；缺少插件能力则记待办，不冒称已连接或可点即用。
9. **按Excel原词制作视频**：逐字读取已审核Excel中该镜的视频完整提示词，严格按[Excel原词执行规则](generation.md#视频提示词以已审核Excel为唯一执行来源)填入、读回并比对。不得私自现写、从中间JSON重组、删掉转场/声音说明或追加音色词；获授权修改时先更新Excel及版本，再读取执行。真实生成只在当前明确授权内提交，结果未知先核对，不重复付费提交。
10. **OpenCut剪辑、字幕与导出**：取得并核对真实视频/音频文件后，用OpenCut按分镜顺序、剪辑出点和声音跨切说明剪辑；字幕依据已审核原文与实际语音自动配置，对齐声音并校对。字幕默认**宋体（SimSun）、白字（#FFFFFF）、黑边（#000000）**，核对实际渲染字体、可读性与安全区。实际调用前阅读可用的opencut-local技能；其他宿主核对其实际OpenCut能力。保存可续做工程入口，实际导出视频并检查文件、画面、声音、字幕和切点；不拿时间线JSON、字幕文件或其他工具单独合成冒充OpenCut成片。能力缺失如实记录，不更换产品后宣称完成。

审核证据绑定具体文件版本/指纹与适用范围；已明确通过或明确修改授权沿用，不重复求同一确认。源内容修改时只更新受影响的审核和依赖状态。批次、模型能力或工具分工可以改变技术执行方式，不能改变以上先后关系或替代用户审核。

第4–5步必须从已选角色阶段和本镜表演解析实际资产：缺所需表情时按 [表情资产](expression-assets.md) 在既有范围内生成/复用并审图，调用前按 [执行检查](execution-checks.md) 核对first_frame附件，调用后对照真实参数记录并实际审图。第9步完成不自动完成第10步；有设计转场时按 [转场改版与逐项落实](transitions.md#转场改版与逐项落实) 同步两侧输入与剪辑任务，导出后运行delivery核对并逐项回放。检查失败先修正具体缺口，保持原有审核/预算/范围，不新增用户审批关卡。

## 首先识别任务与镜头边界

- **场次 scene**：连续的故事空间与时间；**小节 section**：剧情段落，可含多个镜头。
- **镜头 shot**：一次连续观察的逻辑单位；**生成片段 segment**：受工具时长限制的一次生成。一个长镜头可以有多个片段，片段边界不自动等于切镜。
- 收集现有剧本、镜头脚本、模型/坐标、成片、参考图、目标画幅和工具。用户已有分镜时先核对并补缺口，不擅自重写。
- 只有坐标时用粗略尺寸和朝向补成占位体，标注假设；模型承担空间和动作证据，外观由参考图补齐。
- 只要求方案或文字表格时，先完成该范围；默认首帧流程不授权顺带生图、视频或恢复暂停的生产。要求制作时再执行已授权的可用阶段。缺脚本或素材时准备独立部分并明确缺项，不伪造图片、视频、工具或任务状态。
- 区分“交付要素齐全”和“原文无删改”。先确定本次为全文版、缩写版还是局部改稿，保留用户原稿与已选版本。明确要求全文或无缩水时，为旁白、对白及语气说明建立原文单元到场次、镜号和声轨窗口的覆盖映射，按原顺序逐字核对；不能把摘要或先前缩写稿重新标成完整版。只有用户授权缩写的范围才可删并，画面重排不默认授权改写发声原句。
- 镜长约束区分硬下限、硬上限和理想目标，理想值不是强制切点或硬上限；按句意、动作与信息节拍先设计观察单位，再分配时间，详见 [导演分镜](director.md#默认交付专业分镜表)。把全文计字、数字实际读法、自然语速、对白停顿与动作留白放进总时长预算，计字只用于估时，不代替导演切镜。全文与片长上限不能同时满足时，保留原文并交付可审阅的实际规划时序，明确冲突和延长片长、授权缩写等可选调整；不静默删文、压缩气口或加速念白来宣称达标。规划估算与实际录音/成片时长分开。

### 剧本拆分的完整句边界

剧本拆分先确定完整句，再安排镜头、时长和平台节点。**一个完整句对应一个文本节点和独立发声生成节点，不能把一句话分摊成多个半句节点。** 完整句边界优先于字数、节拍、机位变化、自然停顿、理想镜长和工具分段方便；“逐字保留”与“没有截断句子”须分别核对。

- 以原文 `。？！` 及等价英文 `.?!` 等句末标点结合完整句意断句，句末连续问叹号、后随的引号/括号仍归原句。逗号、顿号、分号、冒号、换行、呼吸或列举项不是节点结束依据；小数点不是句末。省略号、破折号及含缩写的疑难边界须结合上下文人工核对，未确认不能标为可执行。
- 原句逐字保留，包含说话人、语序及引号的原有归属。`旁白：` 等说话人标签作为元数据不发声；`他宣布：` 等原文引文引导不能独立作半句节点，须与后续完整引文保持同节点。原稿缺句末标点或语义未完时明确缺口，不擅自加句号、改词或删字来通过检查；句号前仍有未完成条件、列举或承接时，人工审读继续拦截。
- 文本节点与画面镜号不是强制一对一。同一句内的动作、构图、机位或非人物切点写在该完整句节点内部，不据此另建分摊该句的发声生成节点，不用声桥或独立配音安排绕过拆句规则。同一逻辑镜头含多个完整句时，各句分别记录节点及所属生成片段；一个发声生成片段只承载一个完整句。无对白/旁白的纯动作镜仍按完整动作和信息组织，不硬造台词或句号。
- 先给完整句、动作、呼吸和停顿留足自然时长。完整句超出当前硬上限时，核对允许的模型/时长及制作路线，保留原文并说明冲突和可行调整；不能在逗号、顿号或气口截断，也不能擅自加速、缩写或删除原文。自然停顿只用于句内表演，生成片段边界只能落在完整句之外。
- 拆分后保存原文到节点、镜号及声轨窗口的映射，逐字核对顺序和覆盖，并检查每个节点的句首、句末、完整句意及上下文。既有半句拆分先合回完整句再重排时序，修订当前规划及受影响审核状态，真实历史调用保留；只更新技能不代表已修订现有项目。

例如原句“就这样，北京春播、高山夏播、南方秋播——一年三代，硬是让他干成了。”须保留为一个完整句节点；“就这样，北京春播、”和“高山夏播、”不能各成一个节点。

节点列表使用 `python "<skill-dir>/scripts/validate_nodes.py" "<nodes.json>"` 检查；输入可为 `nodes:[{id,text}]` 或 `shots:[{shot_id,narration}]`，可选 `source_text` 核对按序拼接与原文一致。列表只收需检查的非空发声文本；纯动作镜用表演包的空 `dialogue` 表示，不作为空文本节点送检。原文与标签分开保存，不把动作说明混入发声文本。表演包同时运行 `validate_performance.py`，核对句子未被生成片段边界截开。自动检查不能证明语义完整或真实说完，报告通过后仍须人工审读及实际逐句试听。

## 风格与情绪先从剧情判断

有剧情或场景时，先判断人物目标、冲突、信息揭示和情绪曲线，结合用户已有偏好，直接采用有依据的视觉方案；简述必要假设，不再让用户选风格或情绪。没有剧情且观感不明时，只问预期风格与希望观众感受到的情绪。选项、内部路由、参数包和提示词都不使用导演或工作室姓名。采用“剧情与情绪 → 风格家族 → 参数锁定”，逐项落实风格、构图、色调、配色、运镜与光影，详见 [visual-style.md](visual-style.md)。

## 视频项目预算

- 开始一个视频制作项目时，先问：“本项目每秒视频的预算是多少？默认每秒不超过人民币1元。”记录在项目现有制作清单或 `production.json`；用户未指定其他金额时采用1元/秒。接续同一项目沿用已记录预算，不每镜重复询问；本技能不凭空添加项目总额上限。
- 每次付费生成前，用当前实际配置的报价核算：本次人民币费用 ÷ 本次生成视频秒数＝元/秒。积分报价须有已核实的积分兑人民币口径及来源，不能猜兑换率；参考视频时长不计入生成秒数。换算不明时先补齐，不能声称符合预算。
- 单价等于或低于预算时，在用户已有授权范围内继续；用户另有“每次确认后提交”的要求仍须遵守，预算本身不是付款授权。单价超出时，展示本次总价、生成时长、元/秒和预算，询问选择“接受超支，继续本次生成”或“调整方案，把费用降到预算内”；未收到选择前不提交。
- 降费可比较当前平台实际支持的模型、画质、参考输入等方案，说明效果取舍并重新报价；不擅自删对白、关闭音频或破坏连续性，也不把缩短时长降低总价冒充每秒价格下降。不自动提高已记录预算；一次超支批准只适用于该次，除非用户明确修改项目预算。
- 重试、补拍和额外素材的实际收费另记入项目累计成本，不用失败或弃用结果摊大成片秒数来美化单价。提交记录保存预算、原币/积分报价、人民币换算依据、生成秒数、元/秒、预算判断及本次授权状态。字段建议见 [production-contract.md](production-contract.md)。

## 制作经验主动回写

用户已要求本工作流持续积累经验。完成一次有新发现的操作或废片自检后，及时把可复用、已核实的规则写回注册来源项目的本技能或对应 reference，再校验并同步到安装副本；不等用户逐条提醒。一次局部修正保持简短，不为每次操作重复追加日记。

记录“适用平台/条件、观察日期、证据、结论和下次怎么做”。稳定操作方法与会变动的报价/兑换率分开；后者注明时效，条件改变时重新核实。仅有猜测或机器转写疑点时明确未确认，不升级为硬规则。项目私有素材、任务ID、账号信息和详细复盘保留在项目内，不复制进通用技能。

已有规则优先合并更新；保留用户原稿、预算和付款授权边界。维护回写验证后按 [维护更新收尾](maintenance-release.md) 沿用用户已有 GitHub 备份／发布授权，自动完成精确范围提交、非强推上传及远端 commit／文件核验，不重复询问同一权限，不由代理自行添加“不发布”限制；没有相应授权不自行公开。来源不可写、同步冲突、缺 Git／权限、网络或远端分叉时保留原文和本地成果，报告具体阻塞，远端未完成则标 `backup_pending`，不能把本机同步报成全部完成。不擅自重启共享服务或提交收费试验。Updream 已核实的积分换算与查询经验见 [updream-ui.md](updream-ui.md#成本查询与换算记录)。

## 先选衔接方式，再写生成提示

| 条件 | 方式 | 下一首帧 |
|---|---|---|
| 同一长镜头超过模型单次时长 | `continue` 同机位续接 | 上一已选片段的真实剪辑尾帧直接作为输入，不重新生图、不换角度 |
| 剧情需要切到新机位，且要承接同一时刻/动作 | `reangle` 换机位接力 | 上一尾帧提供状态，新机位构图预演/Blender图提供布局，原始设定图提供身份 |
| 反应镜、视线切、插入镜等正常剪辑 | `cut` | 按下一镜需要准备首帧；尾帧可做状态参考，不强制改图 |
| 有意跳时、换场、蒙太奇 | `reset` | 新时空首帧，写明断点和保留的叙事联系 |

设计电影感转场时另读 [transitions.md](transitions.md)。转场机制与衔接模式分别记录，前后镜/连续阶段提示词、剪辑切点或合成区间都进入分镜表；跨场景的动作/图形呼应不冒充continue。遮挡、模糊或白场另需清楚状态与B场布局，不能只凭无信息尾帧猜新场；continue仍原样使用真实尾帧。

有叙事需要的镜头变化可用尾帧换角度；本轮镜长约束允许或用户已明确授权的连续镜头，超过工具单次生成时长时用尾帧直接续接。工具分段不强迫切机位，也不解除用户的单镜硬上限。**不要让每一小节或每个片段都换角度，也不要让全部镜头都同机位续拍。**

任何接力都以已选视频的实际画面为依据。原首帧、脚本预计尾帧、白模尾帧不能冒充实际生成视频尾帧。详见 [frame-handoff.md](frame-handoff.md)。

## 连续有声 AI 短片的实践约束

处理连续生成、对白/OS/系统音或多人打斗时，先读 [ai-video-continuity.md](ai-video-continuity.md)。它补充原文发声覆盖、参考图职责、解剖与视线、实际成片偏差处置、提交与验收状态。用户指定的平台和本次授权优先，不将某次试片的时长、费用或镜头编号写成通用默认。

## 按任务规模执行这条链

本节是上述主流程各阶段的技术细则，不是跳过文档或含图Excel审核的另一条捷径。导演设计在文档获通过后落实到Excel；生图限第4–5步及当前授权，视频制作限第7–9步，剪辑按第10步使用OpenCut。

1. **导演设计**：先读 [visual-style.md](visual-style.md)，根据剧情直接确定风格与情绪，输出六项视觉参数包；再读 [director.md](director.md) 和 [lighting.md](lighting.md)。标出信息揭示、情绪转折、动作因果；确定场次观察立场、构图规律、色调/配色、材质与光线基线，再把逐镜起落构图、运动触发/路径/节奏、焦点、视觉变化与切点理由写进分镜表。固定镜头也有选择理由，不套全场慢推或复杂运镜配额。涉及高级运动、对焦或时间设计时读 [camera-language.md](camera-language.md)，区分机位、变焦、移焦与时间映射；类型名称须展开为逐阶段起落构图、触发、路径/速度、焦点和针对性验收，完整提示词逐镜入表。涉及角色表演时按 [表演提示词编译器](performance-compiler.md) 将意图编译为可见部位、主动作、对白语音参数与时序；表演摘要回填分镜表，结构检查不能冒充表演或口型验收。
2. **统一状态**：建立人物、服装、道具、空间、光线的固定设定和当前动作状态；分配稳定的 scene/section/shot/segment ID，记录在制作项目的 `production.json`。字段与示例见 [production-contract.md](production-contract.md)。
3. **首帧与按需预演**：按 [first-frame-previz.md](first-frame-previz.md) 为每镜准备已选类型首帧并审图入表，已有合格正式图不再额外生成白模。采用白模路线时使用内置生图，环境灰白、主角可用稳定身份色。复杂空间、接触或运动确需且已授权时再按 [blender.md](blender.md) 做三维预演，不把静态图称作实测轨迹。
4. **生成引导片**：只有目标模型实际支持参考视频/结构控制时，按它的要求另制干净、运动连续的引导片；导演预演的停格、标注、跳姿不能直接当控制视频。
5. **首帧/关键帧**：首镜用已选构图预演或白模机位与正式设定图生图；`reangle` 加入前镜真实尾帧；`continue` 直接使用前段尾帧。逐图标明构图、身份、状态、风格的职责。大量必须读准且随 AI 画面生成的文字，先生成文字完整呈现的中间关键帧，逐字校对并固定排版后再进入视频生成；后期加字的路线保留无字画面。具体流程见 [generation.md](generation.md#大量画面文字先做中间关键帧)，其他画面同样先审图再做视频。
6. **能力适配与生成**：核实当前工具的图片输入、首尾帧、参考视频、扩展、时长与尺寸字段；再选择支持的路线。不硬编码某品牌的最大时长或虚构参数。片段内容以Excel原词为准；参数或路线不兼容时记录差异，确需改词先按授权修订Excel，不从字段现写替代词。模型支持首尾双帧不构成自动生成尾帧的授权。
7. **片段接力**：每次选出视频后定位实际剪辑出点、提取尾帧并检查，按 `continue/reangle/cut/reset` 制作下一输入。依赖实际尾帧的片段顺序执行；可先并行准备剧本、空间和独立设定图。
8. **剪辑与验收**：在OpenCut按完整逻辑镜头/场次剪辑并回放，默认宋体白字黑边字幕；检查信息揭示、动作、机位、速度、焦点、明暗层次、世界光向、视线、身份、声音、字幕与前后接点。去掉重复接帧但不破坏动作时序；不以单段漂亮代替整段连贯。

核心主表逐镜展示完整当前视频词、声音/负向约束、选中首帧、四类最终参考及节点/依赖和生成设置，不只给链接、摘要、变量占位、“同上”或一个镜头示例。其他生图/资产规划和实际执行原词按类型、版本在附表保存；当前词只在主表维护，必要复用展示同步核对。未审规划、不适用项与缺失模型/资产如实标注；continue不重画起帧。细则见 [generation.md](generation.md#每镜完整提示词必须入表)。

## 内置本地工具

`scripts/frame_bridge.py` 使用现有 FFmpeg 精确提取显示顺序尾帧，并记录来源文件和图像指纹。Python 标准库即可；FFmpeg 可由 `--ffmpeg`、`FFMPEG_BINARY`、PATH 或已安装的 `imageio_ffmpeg` 提供，不会自动安装或调用网络。

```powershell
python "<skill-dir>/scripts/frame_bridge.py" extract "<project>/clips/SH010_SG01_v01.mp4" --out "<project>/handoffs/SH010_SG01_tail_v01.png"
python "<skill-dir>/scripts/frame_bridge.py" verify "<project>/handoffs/SH010_SG01_tail_v01.json"
```

`--frame-index` 是从 0 开始的解码显示帧编号，可选择候选剪辑出点。使用更早帧时，先把实际前片出点调整到那里并确认，再从最终保留片段重新提取尾帧。验证命令只证明文件来源未变，不证明脸、动作或构图正确。

表演包本地检查：

~~~text
python -X utf8 "<skill-dir>/scripts/validate_performance.py" "<project>/direction/SH010_performance_v01.json"
~~~

只检查结构、声明和原文覆盖；退出0仍须语义审读，实际视频另验，详见 [表演编译与回退](performance-compiler.md)。

人物/表情实际附件与转场输出证据检查使用 `scripts/validate_execution.py`，first_frame用于首帧输入，delivery用于剪辑交付，命令、数据映射与证据边界见 [execution-checks.md](execution-checks.md)。从现有登记导出真实数据，文件存在与指纹相同不证明表情自然或效果已做出；仅规划文字不要求伪造执行快照。

## 操作边界与状态

- 生图优先当前内置图像工具；本地参考先实际查看，依工具当前参数传入，不以提示词中的路径代替图片附件。
- Blender 可通过可用桥接或本地后台脚本执行；找不到Blender时交付机位与场景计划，仅把该三维验证阶段标为blocked，继续可独立完成的静态生图预演；不把说明文档称作已渲染。
- 没有已连接的视频生成能力时，交付逐片段提示、图片、引导片和素材映射，标记待提交。制作skill的请求本身不授权生成示范影片或付费测试；用户要求分镜首帧预演时，按范围使用已提供的内置生图能力，不为普通白模预演索要API key。
- 实际制作时沿用用户已授权的范围和预算，不重复询问；确实需要的外部授权只在素材准备充分后提出。Tripo 实际请求遵守用户既有 dashboard 规则，本 skill 不隐含调用 Tripo。
- `planned / ready / submitted / generated / reviewed / selected / stale / blocked` 必须与现有文件和实际检查相符。生图或视频失败可在已有授权内针对性修两轮，仍失败则改变设计或交付具体阻塞；不无限重试付费任务。
- 前段改版后先把所有依赖尾帧的后段标 `stale`，核对状态、构图、动作时序和素材来源，确认不受影响的后段才重新标记可用。
- 用户暂停、改稿或改为仅文字时，立即撤销旧范围的排队工作并通知并行执行者，不继续旧版补图、重试、续片或自动化生产。对已在途且无法确认取消的请求，记录真实状态；已返结果可保留为历史，未返不能冒称生成成功，也不因沉没成本继续提交。
- 并行只分给能独立推进的文本、资产、镜组或审阅包，明确唯一负责人、可写目录和依赖；共享脚本、工作簿与主工程由一人合并，不让多人同时改同镜同版。有三个独立包时可三路并行，但不把某项目的人数下限泛化为所有任务要求，也不为凑数造无关工作。
- 用户明确要求跳过某项检查时遵循其选择并标记未检查，不能因此报告通过；除上述用户指定的文档与含图Excel审核及当前明确要求外，不额外设置审批关卡，也不把已有通过的同一版本重新送审。

## 交付前检查

- 主表入点、出点及已知帧数已按 [栏目合并规则](director.md#默认交付专业分镜表) 合入A列“镜号／时间”；帧率未知时没有猜算帧数。独立时长列沿用用户模板，精确剪辑元数据仍可追溯；可选“参考对应”未重复四类参考或混入历史日志。
- 只读核心主表即可取得必要分镜、当前完整视频词、实际首帧与四类最终参考、可复用节点/依赖、生成设置及审核/缺口；主表视频词是单一维护源，其他展示逐字同步。待审核或输入未就绪时没有冒称最终可执行。
- 接手者可从Excel导出原图或从交接包相对路径/授权链接取得同版原图；缩略图、本机绝对路径及他人不可访问的平台节点号没有被当成完整交接。平台未创建项与未知参数明确标记，真实执行历史没有被当前词覆盖。
- 有剧情已直接推导并说明风格/情绪依据；没有把选择姓名变成用户任务。六项视觉参数包与逐镜风格、构图、色调、配色、材质和光影相互一致。
- 每镜正文能说明叙事变化、起落构图、运动或固定的选择、焦点与打光结果；不以焦距数字、运镜术语或“电影光”代替设计。复杂运镜有可观察的收益。
- 表演执行文本已去掉抽象心理词，台词逐字保留；线索确实可见，动作/语气/时序能读懂。自动检查、语义审读和实际成片验收分开记录，负向与音频字段符合实际工具。
- 镜头、完整句节点与生成片段区分清楚；按[完整句边界](#剧本拆分的完整句边界)核对节点未在逗号/顿号/气口截断，句中画面切点没有变成分摊台词的独立节点；已运行自动检查并另做语义审读。切镜有句意、动作或信息依据，镜长符合本轮硬约束，超过理想目标有叙事或完整表演理由；工具分段没有被误当成强制换机位，长句超限冲突如实保留。
- 各镜/片段的完整提示词已在表格中逐项展示，正文、原文台词、参考职责及版本/执行状态与分镜和选图对应；未用“同上”或单镜示范代替全表。
- 专业分镜有对应镜号/版本的已选类型单幅首帧和实际目视记录；正式图可直接复用，不额外要求白模。起幅没有偷换成揭示后的落幅；使用白模时身份色未写回正式配色。缺图或未验证项如实标明。
- 接力图来自实际选中版本和实际出点；`continue` 不重新绘制首帧；`reangle` 只改变机位，不无故重置动作。
- 关键道具持物手、视线、空间朝向、服装、光线连续；镜像和二维裁剪不能冒充新机位。
- 专业知识载体已有独立完整物品资产提示词和清楚的正视/展开/局部内容参考，内容贴合年代、学科与用途；来源、事实/设计性质、文字和结构关系及实际审图状态可核对，资产稿通过不代替入画融合或视频验收。
- 首中尾图、运动回放和最终接点检查实际执行；未检查项明确记录。
- 人物阶段和所需表情参考已与实际附件逐项对应；表情不适用有剧情/景别依据。首帧逐人视线与可见眼眉嘴已实际审图，缺表情或沿用中性脸的图未冒称通过。
- 原稿/Excel所有已设计转场均已映射当前两侧素材与剪辑任务；按delivery核对后，最终输出逐项回放及音轨检查有对应版本证据，待剪辑或stale项未随视频生成成功而结项。
- 所有文件在项目内有版本与来源；没有拿过期前镜的尾帧给新后镜使用。

导演分镜脚本默认用专业分镜表交付，格式与执行要求见 [director.md](director.md#默认交付专业分镜表)。展示镜头选择理由、实际可用的接力对照与成片及保存路径；内部任务、费用和接口记录按需另附，不混入导演主表。

## 逐镜交付逐项核对

完整脚本沿用 [专业分镜交付](director.md#默认交付专业分镜表)：以核心主表整合必要分镜、完整当前视频词及最终参考节点，附表保存六项视觉参数/场次美术、原稿、资产与历史证据；叙事摄影、视觉美术、完整提示词三类设计语义都保留。模块读取只控制内部资料获取，不规定平行三表或固定表数，不能丢失必需内容；重复时间与索引按规范合并，当前词和选版保持单一来源。

先按剧情设计各分支，再按同一shot_id逐行合流核对；分阶段读取后也要把完整结果整合回脚本，不让用户拼装碎片。

| 每镜检查部分 | 必须能在脚本中审阅的内容 |
| --- | --- |
| 叙事与时长 | 新信息、情绪节拍、动作因果、全局时间码与镜内时序 |
| 摄影与空间 | 景别、机位/焦距依据、起幅/揭示/落幅构图、前中后景、触发、路径/速度、焦点、时间处理、停留与切点；固定机位同样交代理由 |
| 风格与美术 | 媒介/材质、色调、主辅及强调色各自承载物、构图规律与本镜变化 |
| 光影 | 光源来源与世界方向、光质、明暗层次、人物穿越光区的变化，规划值与实测分开 |
| 表演与声音 | 具体可见行为、逐拍动作、原文台词、语音/声音时点、画外声与口型职责；无对白如实标注 |
| 连续性与输入 | 角色/道具/手别/空间/光向、接镜方式、真实尾帧及参考职责和版本，依赖未取得时保持待上游 |
| 预演与提示词 | 同镜号起幅图、完整白模词、正式首帧词、视频词、对白/声音和针对性负向约束；每条独立可复制，不能用同上、摘要、文件链接或未填变量代替 |
| 状态与回退 | 每项实际生成/检查/选择状态、缺失和未验证原因、风险及保留叙事作用的回退 |

每个部分都要过一遍；不适用则说明原因，不凭空补台词或重画continue首帧。白模身份色不改正式色。实际生图原词保留，重建/修订词另标版本；图片不证明轨迹/表演/焦点/音画已经成立。结构校验通过只证明检查的结构，不证明“专业效果通过”。有缺项先补齐用户授权内可完成的部分，无法完成的准确标出，不把缺图、未执行视频或能力未知冒充已验收。
