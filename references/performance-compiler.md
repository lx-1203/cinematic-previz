# 表演提示词编译器

## 1. 元信息与职责

模块名：表演提示词编译器；模块版本1.0，数据schema_version=1。属于星迹的AIGC，不改技能调用名。适用于从剧情、角色行为、对白或表演意图准备AI视频提示；具体适用模型由当前能力记录决定，不预设某品牌支持负向、音频或首尾帧。只做提示词时不需要连接收费工具。

输入是“谁、发生什么、要说什么”，输出是**变量、规则、时序、正向提示、针对性负向约束、校验与回退记录**。不要求用户先写参数。剧情足够时直接编译；缺项可合理推断并逐项注明，未知关系、身份、模型能力不编造。风格沿用 [visual-style.md](visual-style.md)，不出现姓名透镜。

## 2. 输入字段

以下是作者侧意图字段，不是平台API请求体：

| 字段 | 含义与缺省 |
| --- | --- |
| actor / event / relation / scene | 出镜者、实际事件、人物关系、空间时间；优先从原稿提取。关系不明保留未知，不凭空补亲属关系 |
| dialogue | 说话人、逐字原句、镜内/画外/心内声/系统音；没有对白为空数组，不能补一句台词凑表演 |
| shot / duration / ratio | 已有景别、机位、运镜、时长、画幅优先；推断值标为规划，给动作、停顿和完整对白留时间 |
| model / capabilities | 模型ID及已核实输入、时长、音频和负向能力；未知为null，不能当true |
| style_profile / constraints | 既有视觉方案版本、角色身体形态、持物手、接触、原稿边界、首尾状态和真实素材职责 |

允许用户只给一句意图，编译时补齐上表。情绪词可留在source.intent和内部分析中，不直接作为表演执行指令；原文对白单独保存，不因含“开心”等词而篡改。

## 3. 编译管线

1. **解析**：提取角色、事件、关系、说话人及原句，读取既有镜头/素材。分开原文、推断、尚未核实项。
2. **拆拍**：建立初态→具体触发→可观察落点，至少两个有时间范围的表演节拍，通常用三个。拍不是切镜或模型片段；原稿要求保持时不强造哭笑变化。
3. **映射**：把意图标签转成可见部位与可听行为。先看身体形态和景别，选择少量有辨识度的线索，不同时堆满眼眉嘴手肩。
4. **参数化**：每拍一个主动作声明，记录执行者、动作ID、接触对象与起止；维持同一握持不算重新握一次。另写听者反应、呼吸和表情细节。语音至少给两个具体参数，通常写音量、语速、停顿、气声、尾音；数值是规划，试听后才能确认可说完。
5. **镜头化**：检验脸、眼线、手与接触点是否在画面内、光下可读。全景/背影/面具不能要求看清嘴角颤动；可改用肩背、手、重心或声音，保留用户指定机位。把动作和表演写回分镜表，并将每镜完整正向/负向与语音计划展示在逐镜提示词表，不只埋进JSON。
6. **约束与适配**：总是产出针对本镜风险的负向约束清单；只有模型实际支持才送入负向字段，否则转为正文中的保留状态、参考/构图策略与验收项。原生音频未知或不支持时单列配音/口型方案，不声称对白已生成。
7. **校验与回退**：先跑本地结构校验，再审读动作因果和提示一致性；错误回对应步骤改写，检查通过后交付可提交的文字包。视频生成后的表演和口型另验，不能把文字计数当成实际表演效果。

## 4. 规则库

### 抽象词检查范围

执行文本不写：难过、开心、生气、委屈、悲伤、激动、复杂、深情、痛苦、撒娇、求证、强撑。它们只作意图标签；“先强撑笑意”仍未完成编译。正向动作、逐拍动作、触发说明、语音描述与片段状态都需检查。**原文台词豁免，但须与source.dialogue逐字、逐说话人、逐顺序匹配**；不得借豁免把讲戏说明塞进台词。

词表是中文第一道筛查，不能识别所有同义词、外语或文学心理描写；语义审读还要检查“她意识到、她觉得、心里想”等不可见内容。全片的风格/情绪分析仍可使用情绪词，不能对所有文档机械全局删除。

### 可观察线索候选

| 通道 | 可选择的变化 |
| --- | --- |
| 眼与视线 | 先看具体对象、移开、重新停住；眨眼次数或速度变化。眼眶湿润只在角色和剧情适合时使用，不自动安排落泪 |
| 眉与嘴 | 眉头向内、嘴角抬起后停住、抿唇、说完后闭口；发声期间不能又要求嘴完全不动 |
| 呼吸、手与身体 | 句前吸气、呼气后肩落、手停在接触前、指尖收紧、重心前移；动作必须有空间和解剖依据 |
| 声音 | 音量、语速、具体停顿、气声、尾音；按角色和语言设计，不固定所有人都轻声慢说 |

| 内部意图 | 一种可选编译（不是固定情绪配方） |
| --- | --- |
| 想确认对方答复 | 目光停在对方脸上，句末停住等回应；语速略减、按原句设计尾音 |
| 请求亲近 | 身体略靠近、目光停留、声音放软；不自动加撅嘴、晃肩或幼态动作 |
| 尝试维持笑容 | 嘴角先抬起、开口前停顿、句末闭口仍维持小幅上提；有原稿依据才加入眼眶湿润 |
| 压住冲突反应 | 手停住、下颌收紧、呼气延长，音量压低；是否凝视或移开由人物关系决定 |

同一姿态可有多种含义，先有事件与关系才选择线索。演员的年龄、身体形态、个性和用户明确风格优先。

## 5. 输出数据与提示词模板

完整可运行样例见 [performance-example.json](performance-example.json)。编译器先由宿主模型理解原稿并填写该结构，本地Python只检查声明和组装文本，不是自然语言理解引擎。

| 输出字段 | 类型／要求 |
| --- | --- |
| schema_version / source | 整数1；source.intent原意，source.dialogue为speaker_id/text/mode原文清单 |
| actors / trigger / inferences | actors含稳定id和visible_channels；trigger含具体event及provided/inferred来源；inferences逐项记录field/value/reason |
| shot / capabilities | shot含id/duration_seconds/ratio/framing/camera/style_profile；capabilities含model、verified与nullable的negative_prompt/audio/max_seconds |
| beats | 至少两项；每项id/start/end/trigger、一个primary_action对象（id/actor_id/text）、cues数组（actor_id/channel/text）。时间为该逻辑镜头内秒数，连续覆盖全长 |
| dialogue | 每句speaker_id/text/mode/start/end/voice；mode为on_screen/off_screen/voiceover/system；voice从volume/rate/pause/airiness/ending至少选两个具体参数。无对白为空数组 |
| segments | 一次生成的规划，含id/start/end/handoff/start_state/end_state；第一段start，后段continue，时间连续覆盖全镜。新机位另立shot包，不能借分段换镜 |
| positive_prompt / negative_prompt | action为不含对白原句的可见执行文本；negative_prompt为本镜风险清单，原文对白只从dialogue读取和拼接 |
| 质检报告（另存） | 自动错误、计数、音频/负向送入方式、组装正向词、对白计划、语义待审项和视频状态；不采用输入里自报“通过”的quality字段 |

visible_channels常用eyes/brows/mouth/hands/shoulders/body/breath；也可按非人角色填写ears/tail等实际可见部位。脸部确实可读时，给至少两个面部通道线索；只有一个面部部位可见或脸完全不可见时，转用实际可见部位，不强塞不可见微表情。结构检查只核对声明，真实可见性仍需看图或预演。

**正向模板：** 主体与场景 + 具体事件 + 初始可见状态 + 按节拍发生的动作、视线与呼吸 + 落点 + 既有构图/光线/身份连续性。原生音频已核实支持时，再附说话人、原句、发声时段和语音参数；其他情况单独交付对白计划。OS用心内声路线，人物不做对应说话口型；只有引号内的原句允许发声。

**负向模板：** 从本镜风险挑选，例如“握持无故断开、手指穿插、人物身份漂移、口型与原句不匹配”；不要固定粘贴“长时间静止、眼神空洞”等可能禁止本镜设计的词。克制、停顿、凝视和听者保持不动均可有叙事作用。

## 6. 本地质检与证据边界

Python标准库，无网络、无生成费用：

~~~text
python -X utf8 "<skill-dir>/scripts/validate_performance.py" "<project>/direction/SH010_performance_v01.json"
python -X utf8 -m unittest discover -s "<skill-dir>/scripts" -p "test_validate_performance.py"
~~~

CLI输出JSON；退出0仅表示本次自动结构检查通过，1为需改写，2为输入文件/JSON读取失败。源文件不被改写。自动检查时间连续覆盖、有限数值、角色引用、可见通道声明、逐字台词、每拍单个主动作对象、至少两个语音参数、负向约束存在、已核实时长上限和规划状态承接。计数由数据重算，不接受自报质检数字。

报告automatic_checks=passed仍返回status=needs_review，semantic_review=pending，video_review=not_run。一个动作ID里藏了多个独立动词、两个节拍实际没有信息变化、对白时长不自然、嘴角被挡住等，不能靠结构检查证明。语义审读要逐项给判断和依据；生成后再逐段回放，检查接触、眼线、动作重复、口型、声音和身份，不伪称已看过视频。

未知音频/负向能力时，对应transport分别为separate_or_unverified和constraints_only，不擅自构造请求字段。compiled_positive_prompt是逻辑镜头的文字草稿，不自动上传或提交。多生成片段必须由编译者按实际接点另外写每段变化量，不能把整镜提示和整句台词复制到所有片段。

## 7. 分段与失败回退

| 发现的问题 | 回到哪里与怎么改 |
| --- | --- |
| 抽象心理词进入动作 | 回映射，改成可观察线索；原句有同词则保留台词并核对原文 |
| 无触发或无可读落点 | 回解析/拆拍，补事件因果；不为数字硬加哭笑 |
| 微表情与景别冲突 | 回镜头化，改为可见部位；用户允许时才调整机位，不用数字计数冒充可见 |
| 同拍有互相竞争的主动作 | 回拆拍，按因果排序或分镜；同一动作的延续与自然伴随细节可以保留 |
| 语气笼统或对白说不完 | 回参数化，留动作与停顿时间，试听或用现有录音核对；延长/合理分段，不删原句或异常加速 |
| 模型时长/输入不满足 | 回能力适配。依据当前模型可选时长与自然停顿规划，不采用“≤4秒一段、5—8秒必拆”的统一公式 |
| 跨段重做动作 | 读取上一选中视频真实末态，按 [frame-handoff.md](frame-handoff.md) 原样续接；本JSON里一致的规划状态不是真实尾帧证据 |
| 有负向字段但能力不明 | 保留制作侧风险清单，转为正向保留状态和验收项；核实支持后才送入对应字段 |
| 文字合格而成片失真 | 按实际偏差回首帧、动作、镜头或语音路线；保留预算与授权，沿用 [generation.md](generation.md) 的重试边界 |

一个7秒表演可只有一个生成片段，也可以因实际工具上限分段。表演拍、逻辑镜头与模型片段始终分开。首尾帧只表达起终状态，中间动作仍要验证；图生视频写相对实际首帧的变化，不把参考图称为身份硬锁。多人互动保留事件全貌，以一个主要发起动作配另一人的可读反应；复杂接触可拆拍或预演，不删除另一角色必需动作。

## 修正后的病房示例摘要

原意保留：“妈，现在换我陪你了。”一个主动作是双手包住妈妈右手，之后维持；不再同时安排第二个俯身主动作。0—2秒合拢双手并小幅微笑，2—5.5秒保持接触、句前停顿后说原句，5.5—7秒闭口、维持小幅嘴角上提和视线，呼气后肩落。7秒与近景是有标注的规划，不是用户原话，也未试听验证。

示例能通过自动结构检查；语义和生成效果须按实际检查分别记录。未确认模型前，附对白计划与负向约束，不宣称原生音频、口型或负向字段已经生效。
