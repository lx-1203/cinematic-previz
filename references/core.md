# 共享范围与操作边界

此模块每次读取都会带入，只保留跨任务边界。完整规则的归属与入口见 [模块读取说明](module-loading.md#公共规则的正式来源)。

- 先识别本次范围。查询一种方法、写提示词、只改首帧或维护技能，不自动启动整片制作、收费测试或平台任务；只做用户当前要求的部分。已有项目从获准阶段接续，保留原稿和已选版本，不擅自改写台词、身份、关系或衣装。
- 素材先按当前任务的叙事或独立控制用途筛选，再核版本与来源。参考类别不是数量配额；不为填栏制作、裁切或上传无必要图片，不把历史素材清单直接当本次上传清单。已有整图与文字足够时直接复用；真实奖状、手迹、关键结构等确需保真的输入仍保留。
- 进入制作前按 [阶段与审核](workflow.md#制作阶段与审核顺序) 加载 `stages` 及当前专项模块。新项目先审文档，再做Excel分镜和资产首帧；含图Excel通过后才能进视频制作。沿用同版通过证据，审核不解除“仅草稿/不提交”等范围限制；不额外增加审批关口。
- 风格、机位与常规设计从剧情和已有偏好推导；参考或身份缺项按对应资产规则处理，不编造来源。生图优先宿主内置能力，本地图片须实际查看并通过附件输入，文件路径不代表已传入。复杂空间按需要使用三维预演，缺Blender只标该阶段未执行，不阻塞独立可做部分。
- 实际生成先核对 [预算与授权](workflow.md#视频项目预算) 和工具能力；默认预算不是付款许可。不因已连接账号、已有余额或初始化节点而提交。Tripo请求另遵守用户的dashboard要求，本技能不隐含调用授权。
- `planned/ready/submitted/generated/reviewed/selected/stale/blocked` 与真实文件和证据一致；规划、结构检查、静态审图、三维轨迹和实际音画分别验收。工具或素材缺失时准备可独立部分，按[缺素材通知](generation.md#资产缺口自动补齐)直接告知用户，不虚构ID、渲染、提交或验收。
- 在既有授权内针对性修复两轮仍不成立时，改变可行方案或报告具体阻塞，不无限付费重试。更改上游后标记受影响依赖为stale，核对后再恢复，保留历史执行原词。
- 用户暂停或改为仅文字时停止旧范围排队及重试；在途请求记录已知状态，不因沉没成本继续提交。多人工作只分配独立包，指定负责人、可写范围和依赖；共享主表与同镜同版由一人合并，不为凑人数造任务。
- 沿用会话已有授权；确需新增外部权限时先准备具体可审阅结果。用户明确跳过检查时标未检查，不报告通过。维护修改按 [维护收尾](maintenance-release.md) 核验本机同步和已有授权要求的GitHub备份，二者分开报告。
