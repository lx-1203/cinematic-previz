# 时间与完整句

本文件是生成时长、剪辑时长和完整发声单元的正式定义；分镜、表演、生成与示例引用这里，不各自重新定义范围。

## 先核算朗读再排15秒大段

**默认顺序：完整原句 → 逐句朗读核算 → 旁白窗口与动作留白 → 每15秒一个多镜大段 → 包内小分镜 → 完整提示词 → 保存文件联合校验。** 一个大段是一次计划生成任务，使用 `multi_shot`，内部可有多个景别、机位和1—3秒的小镜；不是15秒一镜到底，也不是每个小镜另提一次请求。主表和提示词指导按同一包ID一包一行，内部小镜保留自己的镜号与时序；每包只维护一份完整执行词，不逐小镜复制成独立任务。整片时长由朗读、动作和过渡算出后安排为15秒大段，不固定为某项目的8包/120秒。

先保留每句原文，另写数字、年份、百分比及外语的实际读法；按目标声线的自然语速估算朗读，记录计数方法、音节/词数、语速、标点与呼吸停顿和逐句预算。中文无指定声线时可用每秒3.2音节作初步假设，必须标明是假设，可根据真实声线调整，不能为硬塞15秒擅自加速。原文不能改成数字展开版覆盖保存，也不能只按原文字符串长度计时。

有可用的本地或已授权试读时，测量真实音频并列明声音、参数、文件与时长，给自然停顿和动作留余量。没有试读只标估算，不把文字计数写成实测，不为测时自动提交付费配音。最终配音选定后按实际音轨逐句复测；试读参考不冒称正式旁白。无可朗读台词/旁白时先核对原稿，记录“无朗读文本”，不编造发声句；呼吸等非语言声音仍按声音模块处理。

逐句预算不得少于合理估算或已有试读时长。排完整句声轨窗口后再排画面大段，另给句间、换场和动作收束留时长；不要把同步发生的画面时长与旁白时长重复相加。独立旁白可用同一条完整句音频跨15秒包界连续播放，不截成半句音频、不重读；镜内发声仍受完整句和真实模式能力约束，冲突时保留原文并调整方案，不机械截断。

Excel保留“原文与旁白”和“朗读测时”：后者按发声单元对应朗读文本、计数、停顿、估算、试读（可空但如实标未实测）、规划秒数、余量及覆盖包ID；沿用当前表头。默认中文估算表B3为语速，表头第5行，正文从第6行逐句连续填写。没有朗读文本时在“朗读测时”A3写“朗读模式”、B3写“无朗读文本”，不能同时留下非空发声原句。自定模板可等价映射，核算不能省略，不增加来源定位列。

导出后运行 `python "<skill-dir>/scripts/validate_excel_layout.py" "<已保存的.xlsx>"`，默认联合检查布局、完整多镜正文、15秒包长、全片时序、朗读记录、实际读法、预算与声轨窗口。缺朗读记录、预算短于估算/已有试读、声轨重叠或越界、包长不符、回退 `single_shot` 均须修复后重验。通过只证明所记规划一致，不证明试读文件真实、自然语速或平台支持；必须核对音频证据和实际表达。

只有用户明确指定其他时长、独立单镜或真正一镜到底，才记录覆盖默认的指令与适用范围，并按该方案核验；CLI的 `--mode`、`--segment-seconds` 仅用于落实这样的明确要求，不是自行绕过检查。目标模型不支持15秒多镜时标能力缺口，准备可审阅调整，不静默拆回4—8秒小任务。旧单镜字段和技术示例保留历史兼容用途，不作为新计划默认。

## 生成片段与剪辑时长

- 场次是连续时空，逻辑镜头是一次不切镜的连续观察，表演节拍是动作或信息变化，生成任务是一次平台请求。一个任务可独立生成单镜，也可原生输出包含多个切镜的完整段落；不能把任务与镜头强制一一对应。
- **显式单镜方案 single_shot：每次4—8秒，仅在用户明确选用时适用。** 低层校验器对未写模式旧记录的单镜解析仅用于兼容，不证明新计划符合默认15秒多镜路线。单镜即使遇到能生成30秒的平台，也不能自动放宽到30秒；旧计划的自定义范围不能自动扩大这条单镜约束。当前平台自身更窄的时长限制仍须同时满足。
- **多镜头整段生成 multi_shot：新规划默认每包15秒，不套单镜4—8秒范围。** 用户明确改时长时遵循所选方案，提交前仍须核实平台、模型、模式支持该时长和包内切镜。15秒是本流程的默认规划，不是所有平台天然支持的声明；还须确认该模式支持一次请求内多镜头切换，不能只看最大秒数猜能力。平台未知时保留规划并标未核实，不把草稿标成可提交。
- 用户在此流程中所称“长镜头/长段”若指一次生成多个分镜，登记为多镜头整段；真正一镜到底仍指画面不切镜。两者不能用同一标签混淆。独立生成每个分镜与原生多镜生成是可选制作路线，按用户意图与实际能力选择，不默认强制逐镜提交。
- 多镜任务保存有序shot_ids、全局时间轴和完整阶段/镜头词；包内镜头可以是1—3秒或其他有依据的时长，不因其短而各自补生成余量。一次提交的是整个包，包内切镜由该次生成完成，不为每个切点额外提尾帧、生成新首帧或另交一个任务。主表按同包ID关联各镜与同一当前执行词来源，不复制多份独立修改的整包词。
- 每个任务记录duration_seconds（实际请求生成的秒数），另记各导演镜头的成片区间和实际剪辑保留范围。独立单镜可从合规4秒生成保留2秒动作，但必须保留必需动作和完整台词；这不意味着多镜包内的2秒镜头需要单独生成4秒。两个层级的时长分别求和，不重复计费秒数。
- 单镜逻辑镜头超过所选单次范围时，可按连续片段接力；多镜整段超过当前平台能力时，按完整剧情和发声边界拆包。只在实际任务之间按需要使用前段真实出点续接、换机位或换场，不在包内每次切镜时重复生成。[真实尾帧接力](frame-handoff.md)仍负责任务之间的真实状态。
- 一个完整句对应一个独立发声单元，不等于一次视频任务只能说一句话。多镜整段可以包含多个完整发声单元及角色轮次，也允许一句话在同包的合理画面切点之间连续说完。不能把换镜当成拆半句、重读台词或擅自改成旁白的依据；包间拆分不能截断镜内发声原句。独立旁白跨任务时保留同一个完整发声单元和真实声轨窗口，不生成多个半句。
- 先给动作、完整对白、呼吸与停顿留时长，慢动作和停顿计入成片时间；不靠空等、异常加速或删句凑数。参数和规划通过不代表实际画面、切点或声音通过。

计划使用generation_segments保存实际请求列表，generation_mode按项记录；旧字段名为兼容入口，不表示每项只能有一个导演镜头。multi_shot项至少包含两个不同shot_ids，并保存platform_limits的verified、max_seconds，以及平台实际提供时的min_seconds/allowed_seconds。另在现有能力记录保存来源、模型/模式与核实日期；这些是本地制作元数据，不是平台API参数。

以下为默认15秒多镜规划字段示例；能力尚未核实，不是已授权任务或可提交参数：

```json
{
  "generation_segments": [
    {"segment_id": "PK01", "generation_mode": "multi_shot", "shot_ids": ["SH01", "SH02", "SH03"], "duration_seconds": 15,
     "platform_limits": {"verified": false}},
    {"segment_id": "PK02", "generation_mode": "multi_shot", "shot_ids": ["SH04", "SH05"], "duration_seconds": 15,
     "platform_limits": {"verified": false}}
  ]
}
```

提交前另运行 `python "<skill-dir>/scripts/validate_duration_limits.py" "<plan.json>"` 核对已记录的平台能力；上例因能力未核实应不通过，不把规划检查冒称平台就绪。duration_constraints和CLI的--min/--max只能在4—8秒内收窄单镜范围，不能借旧配置扩大单镜时长；多镜包始终读取各自platform_limits，缺项或未核实则不通过。校验器核对所声明限制和时长，不证明平台能力来源真实。表演校验器现有schema为单镜表演包，多镜任务按各镜表演和上层完整发声单元分别审读，不把整包伪装为单镜结构来宣称已验证跨镜音画。

## 完整句与发声单元

剧本拆分先确定完整句，再安排镜头、时长和平台节点。**一个完整句对应一个文本节点和独立发声生成节点，不能把一句话分摊成多个半句节点。** 完整句边界优先于字数、节拍、机位变化、自然停顿、理想镜长和工具分段方便；“逐字保留”与“没有截断句子”须分别核对。

- 以原文 `。？！` 及等价英文 `.?!` 等句末标点结合完整句意断句，句末连续问叹号、后随的引号/括号仍归原句。逗号、顿号、分号、冒号、换行、呼吸或列举项不是节点结束依据；小数点不是句末。省略号、破折号及含缩写的疑难边界须结合上下文人工核对，未确认不能标为可执行。
- 原句逐字保留，包含说话人、语序及引号的原有归属。`旁白：` 等说话人标签作为元数据不发声；`他宣布：` 等原文引文引导不能独立作半句节点，须与后续完整引文保持同节点。原稿缺句末标点或语义未完时明确缺口，不擅自加句号、改词或删字来通过检查；句号前仍有未完成条件、列举或承接时，人工审读继续拦截。
- 文本节点与画面镜号不是强制一对一。同一句内的动作、构图、机位或非人物切点写在该完整句节点内部，不据此另建分摊该句的发声生成节点，不用声桥或独立配音安排绕过拆句规则。同一逻辑镜头含多个完整句时，各句分别记录节点及所属生成片段；一个独立发声单元只承载一个完整句；一个多镜视频任务可以容纳多个这样的单元。无对白/旁白的纯动作镜仍按完整动作和信息组织，不硬造台词或句号。
- 先给完整句、动作、呼吸和停顿留足自然时长。完整句超出当前硬上限时，核对允许的模型/时长及制作路线，保留原文并说明冲突和可行调整；不能在逗号、顿号或气口截断，也不能擅自加速、缩写或删除原文。自然停顿只用于句内表演，带该句镜内发声的视频任务不能在句中结束；同任务内的合理切镜不截断声音单元，独立旁白跨任务的条件见上节。
- 拆分后保存原文到节点、镜号及声轨窗口的映射，逐字核对顺序和覆盖，并检查每个节点的句首、句末、完整句意及上下文。既有半句拆分先合回完整句再重排时序，修订当前规划及受影响审核状态，真实历史调用保留；只更新技能不代表已修订现有项目。

例如原句“就这样，北京春播、高山夏播、南方秋播——一年三代，硬是让他干成了。”须保留为一个完整句节点；“就这样，北京春播、”和“高山夏播、”不能各成一个节点。

节点列表使用 `python "<skill-dir>/scripts/validate_nodes.py" "<nodes.json>"` 检查；输入可为 `nodes:[{id,text}]` 或 `shots:[{shot_id,narration}]`，可选 `source_text` 核对按序拼接与原文一致。列表只收需检查的非空发声文本；纯动作镜用表演包的空 `dialogue` 表示，不作为空文本节点送检。原文与标签分开保存，不把动作说明混入发声文本。适用的单镜表演包同时运行 `validate_performance.py`；多镜包另按上层完整发声单元核对，不把旧单镜结构检查冒称多镜整包音画检查。自动检查不能证明语义完整或真实说完，报告通过后仍须人工审读及实际逐句试听。
