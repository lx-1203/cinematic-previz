# Updream：少读目录，少走界面

## 先确认本聊天职责

用户将本聊天分配为插件维护/分流窗口时，只改插件、测试和工作流；制作主窗口负责画布、上传和付费生成。本维护窗口不为复现性能而切换其页面、重启共享服务或认领其项目。用户已有明确分工时不重新询问。

## 已有接口能替代哪些点击

| 操作 | 优先调用 | 限制 |
| --- | --- | --- |
| 找节点、看参考及完整草稿 | find_nodes / get_node | 不按前台或旧名称猜ID；参考字段以实际返回为准 |
| 新建空节点并命名、保存提示词 | create_node | 不等同于完整克隆；核对nodeId、promptSaved |
| 改名、改完整提示词 | update_node_checked | 使用刚读到的完整expected；成功检查verified |
| 更新模型、比例、已上传图片参考 | update_node，再get_node | referenceImages为URL列表，不能把本地路径当已上传图片；没有单图增删接口，先核对完整目标列表 |
| 多个已知节点的移动、连线或更新 | batch | 先查对应实时Schema；一批只核对一次项目身份，逐步仍保留页面校验；无回滚、不自动重跑 |
| 查询模型能力、任务状态 | list_models / get_task_status | 生成时长/尺寸以模型实际能力为准，状态查询建议间隔至少5秒 |
| 提交视频任务 | create_video_task | 只传当前Schema支持字段；原生音频、报价不能猜参数，仍保留用户授权与网站确认 |
| 本地图片快速上传与跨镜头复用 | upload_files / list_assets / reuse_assets | 当前项目素材库；可选普通参考连线，详见[快速上传](updream-upload.md) |
| 虚拟角色库、音频开关/报价、剪辑 | 当前原生目录有相应能力才用；否则UI补充 | 快速上传不替代角色认证或专用首帧槽 |

图片上传一次后保存本地文件SHA256、实际URL、当前参考顺序和用途。下一镜可复用不变身份/场景URL，只有新首帧等新素材继续上传；切换图片列表后更新提示词编号。链接节点不自动证明输入、音轨或报价已配置。

## 按需读取原生工具目录

宿主仍只显示旧工具、需要在不重启制作服务时调用新增上传能力，或需要自动核对当前参考编号/参数/预算时，读[直连与提交前核对](updream-preflight.md)。直连读取真实目录，不代表宿主缓存已刷新。预检只核对实际UI观察数据，不替代现场采集和付款授权。

先看宿主当前updream_list_tools的Schema是否包含`detail`和`toolNames`。旧进程没有新字段时不要反复发送不支持的参数；等制作空闲后安全重载本机共享服务，再让MCP宿主重新发现工具。只重开stdio适配器可能继续复用同版本旧服务，安装源码更新不等于运行服务已经更新。维护窗口不主动打断主窗口的服务。

```json
{"tabId":123,"detail":"names"}
```

仅发现当前注册的名称；123为虚构示例，须替换为list_tabs返回值。确定要修改节点时再取对应参数：

```json
{"tabId":123,"toolNames":["canvas.updateNode","gen.createVideoTask"],"detail":"full"}
```

`summary`返回名称、描述和annotations，省略Schema；默认`full`保留完整目录。点/下划线名称等价，匹配按页面顺序返回；未注册名称不会回退全量。每次重新读取实时目录，不缓存过期Schema，也不把精简视图用于跳过参数验证。

这减少的是代理需要读取的响应体，不减少网站回调数，不加快模型渲染。未完成真实浏览器验收前，不报告端到端提速比例。


## 并发与自动补位

2026-10-20，本机用户已明确确认当前Updream账号的视频并发窗口上限为 **6**；实际提交亦为前6个成功、第7个返回`VIDEO_QUEUE_FULL`。该值是当前账号/配置记录，不是所有平台和账号的通用上限。制作项目记录`max_in_flight_video_tasks=6`，后续默认按6窗口滚动补位；账号或平台能力变化后重新核对。

批量提交是逐项启动、平台并行处理；保留每项taskId和成功回执。只有在已提交任务明确完成/失败、实际腾出空位后，才补交未提交镜头；队列满不重交成功项、不循环盲试第7项。结果未知先查询，用户指定“8镜一批”也不能冒称平台已同时接受8个。
