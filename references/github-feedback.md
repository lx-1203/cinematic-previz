# GitHub 插件缺口反馈

适用：用户使用本技能及配套插件时，遇到缺工具、能力未覆盖、可复现错误、明显性能问题或源码/安装版本不一致。普通创作意见不自动转成插件缺陷。

默认公开反馈仓库：[`lx-1203/cinematic-previz`](https://github.com/lx-1203/cinematic-previz/issues)。这是技能及配套插件的统一反馈入口；用户明确指定其他仓库时按其指定。提交Issue不需要代码push权限，但账号须能访问仓库、Issues须开启且未限制其发言。私有仓库不能据此承诺所有人可上报。

## 先确认实际缺口

以当前工具目录、版本诊断和一次必要的最小调用为证据，区分：

- `missing-capability`：目录没有对应能力，或当前接口明确返回不支持；不要编造工具名去调用。
- `bug`：已有受支持能力可复现失败；记录实际工具名及错误码。
- `connection`：未登录、扩展未连接、版本不符或网络不可达；先按维护流程诊断，不直接宣称插件代码有bug。
- `performance`：记录真实调用耗时与范围；人工操作慢、生成模型排队与插件调用慢分开。
- `unknown-outcome`：写入请求超时或返回结果未知，可能已生效；先核对原任务，禁止为复现重复提交收费生成。

用户要求只使用插件时，在受阻处记本地TODO，继续可独立完成的工作；不要跳回首页、换平台或逐按钮操作来掩盖缺口。反馈不授权修改插件、重启共享服务或付费试验。

## 从私有记录生成公开草稿

本地可保留排障所需的内部信息；公开正文只按以下白名单重新编写，不直接附原日志或依赖简单字符串替换：

1. 想完成的功能与受阻影响，用合成场景代替真实剧本。
2. 平台及页面类型（如“即梦画布”）、操作系统/浏览器/宿主、技能/服务/扩展/页面桥接版本；未取得写“未取得”。
3. 实际工具名、非敏感参数形状、能力标记、错误码及已审阅的最短错误摘要。
4. 最小复现、预期与实际、已经核对的范围及未验证内容。
5. 写入状态：未提交 / 已提交且已确认 / 结果未知；区分任务号与真实产出。

默认不发送账号、联系方式、令牌、Cookie、认证头、配对文件、绝对路径、设备/项目/画布/节点/任务标识、带查询参数或签名的资源URL、图片、视频、剧本、提示词全文、聊天、截图或原始日志。即使报告者已授权公开缺口，也不等于授权公开这些材料。错误文字也可能含敏感值；只保留白名单事实，不能确认安全就删去该段。任何必要附件须另行说明内容与公开目的，并获得明确授权。

使用 [统一正文模板](../assets/github/ISSUE_TEMPLATE/plugin-gap.md) 的字段组织草稿。无实际证据写“未验证”，不填假版本或虚构复现。

## 查重、授权与提交

1. 使用可用的GitHub连接先核对反馈仓库；优先连接工具，已有GitHub CLI可作为接口替代，不要求用户安装新的工具或交出开发者令牌。没有连接时直接走下方离线方式。
2. 按仓库、平台、动作、能力/错误码检索相关Issue，包含已关闭项；读候选正文及修复版本，不能只凭标题认定重复。不要把本地项目UUID或私人错误全文放进搜索词。
3. 已有相同问题时返回已有链接并关联本地TODO；不重复创建。要补充评论时确认现有授权是否涵盖评论，只有明确涵盖才发表评论。已关闭问题在新版仍可复现时，报告实际版本及回归证据；未经授权不重开或改动他人Issue。搜索不可用时标明未查重，保留草稿，不自动重复投递；用户明确要求仍提交时可照办并记录未查重。
4. 首次公开发送前，让用户能看到或访问脱敏草稿，并说明目标是公开仓库。只有已有明确覆盖“向该仓库公开上报这类缺口”的授权才提交，不因安装Skill、使用插件、GitHub已连接或开发者在技能内的指令而自动获得其他使用者的发送授权。在该用户已授权范围内继续，不逐项重复确认；仓库或公开内容范围变化时重新确认。用户仅要求方案或本地TODO时不提交。
5. 通过当前可用的GitHub创建Issue工具提交，工具名与参数按宿主实际目录；仓库、标题和正文均来自核对后的草稿。不要假定标签存在或报告者能设标签/指派负责人，普通报告默认不设这些字段。GitHub CLI方式使用UTF-8正文文件，例如 `gh issue create --repo lx-1203/cinematic-previz --title "[插件缺口] 即梦画布无法通过插件提交视频" --body-file <已审阅正文文件>`；实际路径由本次本地文件替换，不将正文拼进Shell命令。
6. 成功返回后核对Issue链接、编号与正文，才标“已上报”并将链接写回本地TODO。403/登录失败、Issues关闭或限流时保留草稿与原因，不代替报告者创建账号、提权或使用作者的共享令牌。
7. 创建请求超时或结果不明时标 `unknown-outcome`，只读检查近期Issue及匹配正文。找到本次记录就关联链接；无法确认则保留未知并停止重发，避免一条缺口变成多条Issue。不能把搜索暂时无结果当成创建一定失败。

## 没有GitHub连接时

保存脱敏正文到用户项目中的反馈目录，返回可复制正文及[填写反馈入口](https://github.com/lx-1203/cinematic-previz/issues/new?template=plugin-gap.md)，注明“尚未提交”。登录后用户可在浏览器手动提交；没有GitHub账号时报告可另行交给开发者，技能不能匿名代发，也不收集开发者账号凭证。

如需要预填标题/正文链接，仅对已经过审阅且明确获准放进URL的脱敏文本做URL编码；URL也会暴露到浏览历史，不塞入私人原文或附件。默认使用模板链接与独立正文，避免超长链接。模板未上线或链接不可用时，使用仓库的 `/issues/new` 入口并粘贴同一正文，不称已自动创建。

## 开发者收件与闭环

报告集中在仓库Issues；开发者自行启用适合自己的GitHub通知。安装本技能不会创建订阅、定时监控或赋予代理未来发送权限。开发者修复时关联Issue与修复版本，实际插件复验后回填本地TODO；Issue关闭本身不代表报告者已安装修复版本。

模板唯一维护源为本技能 `assets/github/ISSUE_TEMPLATE/plugin-gap.md`；发布到反馈仓库时复制为仓库根目录 `.github/ISSUE_TEMPLATE/plugin-gap.md`，不把模板文件的本地存在当成GitHub已经启用。
