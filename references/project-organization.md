# 目录整理与项目回收站

模块 `organization` 与 `records` 配合使用。按制作职责和生命周期整理真实文件，沿用 [制作登记](production-contract.md)，不另建相互竞争的选版源。本模块规定整理与恢复记录，不提供或冒称自动恢复工具。

## 分类与入口

以下是推荐入口，新项目按需建立；只整理已有内容时不批量创建空目录。

| 入口 | 内容与边界 |
| --- | --- |
| `01_剧本` | 原稿、文档剧本、已登记的分镜工作簿及交接入口 |
| `02_图片` | 人物／场景／表情／物品参考、首帧、关键帧与预览；按职责和来源分层 |
| `03_音视频` | 史料原片、生成片段、配音、音乐、字幕与导出；原始媒体保留来源 |
| `04_工程` | 剪辑、三维、平台映射、脚本及运行所需依赖 |
| `05_历史` | 已被替代且有依据的历史版本、旧交接包；保留内部相对结构 |
| `06_通用` | 跨项目可复用技能、模板、示例与公共资源，保留许可和原出处 |
| `98_项目回收站` | 明确退出本次生产且获准回收的文件，按批次保存 |
| `99_记录` | 分类映射、整理回执、来源／镜号关系、批次清单、异常与恢复记录 |

既有活跃目录、工程依赖、已登记素材路径优先原位保留，以可见入口或路径映射呈现分类；不为统一外观强搬。入口指向真实源，不把浏览复制品改成第二个制作源。已存在的链接只登记目标，不递归盲扫 junction。

移动前解析源、目标及各级父链，确认都在本次明确授权的根范围内；禁止越界或未经核实地穿越 junction、符号链接等重解析点执行递归扫描、移动或删除。确需通过已知兼容入口操作时，先解析并核验实际目标，以实际目标限定范围，不删除入口背后的整棵目录。目标父目录尚未建立时，也要核对已存在父链和拟建路径。入口不构成扩大操作范围的授权。

## 人物目录与阶段文件

人物按稳定 `person_id` 归组，同一人物的所有现用年龄／年代与衣装资产放在同一人物目录，不另按青年／中年／老年分散目录；用 `variant_id` 和文件名明确区分阶段。既有 C00、C01 等 ID 保留映射与历史引用，不以目录顺序重新认定人物。阶段身份和证据规则见 [人物资产](character-assets.md#先盘点全部出镜人物与阶段)，记录字段见 [人物与阶段记录](production-contract.md#人物与阶段记录)。

例如在实际人物根目录下采用 `人物名_person_id/当前/` 集中现用阶段图，文件名采用 `person_id_variant_id_人物名_时期_阶段_衣装_史料依据或AI推演_vNN.png`；“时期／阶段待核”可以显式保留，不补造精确年龄。该格式可兼容已有命名，但文件名须让用户看清阶段、年代、衣装、推演性质与版本。同一 `当前/` 内同时保留仍在使用的不同阶段，不把青年版误当被中年版替代的历史版。

原照、图注和来源裁取放 `来源/` 或指向既有史料库；已被替代的文件版本放 `历史/` 或沿用项目历史入口，均关联真实源和选择证据。AI 彩色／修复版注明派生类型与原照 ID，不与史料原件或当前演员板混称。只建实际需要的目录，来源图不为统一外观强行搬出仍在使用的照片库。

执行已有 Cxx 目录归并时，先核对人物归属、各阶段选版和活跃依赖，再在授权内迁移并更新原路径到现路径及逐镜 variant_id 映射。暂时不能安全移动的保留原位，用明确的入口／映射展示，并标“集中整理未完成”；不得用新增说明或浏览副本宣称实体文件已归并。

## 当前版本与素材关系

先读取真实制作登记、工作簿权威单元格及相应选择证据。较晚修改时间、更大 `v` 号、文件名带“最终”均不代表选中；mtime 只用于侦测变化。无法确定时写“当前版本未知／待核”，保留候选。

兼容既有字段：`workbook` 可能是路径字符串，也可能是含 `path`、`file` 等既有路径字段的对象；按实际结构读取路径、版本和指纹，不把整个对象当路径，不为整理强改记录结构。登记与实物不一致须列明，不替用户选版或改审核状态。

提供“当前工作表／当前审阅材料”入口时，优先每次打开都从登记解析路径，并检查文件存在、类型和允许根范围；路径或登记失效应显示具体问题，不悄悄回退到修改时间最新的文件。宿主不支持动态入口时，保存有版本标记的普通入口，并在选版变更时一起更新，不能声称自动跟随。

史料原片、史料原图、AI 修复／复原、概念设计／生成图分别存放或明确标记类型；派生图关联源 ID、处理方式与版本，不能把 AI 补出的内容标成史料事实。正式选中、备用、退图、待核各自有状态；退图仍可能是后续修图参考，先查依赖。

素材映射至少保留：稳定资产 ID、使用镜号／片段 ID、职责、版本、真实路径、SHA256、来源、选中状态与证据。一个文件服务多个镜号或职责时保留多条关系；同 hash 只说明内容相同，不能据此删掉镜号映射、来源或用途。改名／搬移沿用稳定 ID，并登记原路径到现路径。

浏览副本、缩略图、HTML 展示及分享快照标注抓取时间、真实来源、来源版本／指纹与对应关系，明确是副本。源发生变化则标 `stale` 并按需刷新；未经实时读取不得宣称与活跃制作同步。

历史归档保存过往阶段的有效快照或有依据的被替代版本；退图表示“未选用但可能被引用”；待核表示“状态或归属未知”。三者分开，未知文件不因年代久或未在入口显示就进入历史或回收站。既有回收批次中的待修、事实待核保留原状态，不因所在目录就改成已确认淘汰。

## 可恢复回收与恢复

在用户已有移动授权内执行。先核对工作簿、工程、素材映射、脚本、分享包与活跃任务的引用；保护仍在使用的路径。需要移动时，同批更新授权范围内的引用并核验；无法确认依赖的文件保留原位并记待核。

每批使用唯一批次 ID，保持必要层级与内部相对路径，先写计划清单，再逐项记录实际结果。清单记录原／现路径、大小、SHA256 及校验时刻、回收原因与证据、依赖、执行状态、恢复目标与恢复状态。hash 未计算或原路径未知填 `null` 并说明，不能补称历史批次当时已验证。

默认以可恢复方式保存，不自动永久删除或定期清空。复制后移除原件前先核验目标；直接移动后核验实际落点与内容，失败记录真实状态，不称整批成功。移动中断时逐项定位文件，不猜测全部已搬或已回滚。

恢复前核对现文件、清单指纹、原目标父链和引用。原路径已存在任何新内容时不得覆盖；选择独立恢复目录或唯一名称，记录实际恢复位置与未恢复的原入口。恢复后核验内容和引用再更新状态；无法恢复或无法确定原路径时写原因与“未知”，不臆造恢复位置。

最小批次条目示例（字段可映射到既有记录；`null` 均为未核实占位）：

```json
{
  "batch_id": "YYYYMMDD-B01",
  "asset_id": "ASSET-001",
  "uses": [{"shot_id": "SH010", "role": "edit_reference", "version": "v02"}],
  "original_path": "02_图片/待选/图A.png",
  "current_path": "98_项目回收站/YYYYMMDD-B01/02_图片/待选/图A.png",
  "size_bytes": null,
  "sha256": null,
  "verified_at": null,
  "reason": "用户明确退图，依赖检查后回收",
  "evidence": "对应指令或记录定位",
  "dependencies": {"checked_at": null, "references": [], "status": "pending"},
  "move_status": "planned",
  "restore": {"status": "not_requested", "target_path": null, "evidence": null}
}
```

## 整理前后核验与并发漂移

1. 整理前记录盘点时间、授权根范围、真实入口和登记指纹；按稳定 ID 列出来源、去向、用途、依赖和动作，只遍历实际范围，不跟随链接扩展。
2. 操作前重新核对源大小、mtime、SHA256 与登记；其他聊天或程序写入导致变化时，暂缓该项并记 `stale／待核`，重新读取后再决定，其他独立项可继续。
3. 操作后核对文件数／大小／指纹、逐镜映射完整性、真实工作簿入口、工程引用及分享包内部链接；复制品与源分别登记，不用数量相等替代内容核验。
4. 结束前再检查本次受影响源和登记是否漂移；新增版本不自动纳入旧快照。输出真实目录入口、版本依据、成功／暂缓／失败项、批次清单位置与恢复限制；未运行的验证明确写未验证。
