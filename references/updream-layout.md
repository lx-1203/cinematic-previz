# Updream 节点排版与验收

新增或整理当前任务的画布节点时读取本模块。用户已有明确布局优先；常规排版属于本次制作整理，不要求用户逐次选坐标。仅查询、只改现有提示词或只检查连接时，不顺手重排画布。本规则不提交生成任务、不增加素材、不控制桌面鼠标键盘。

## 可复用的默认结构

- 按本项目的片段／场次分区，顺序来自当前剧本和制作映射；每区采用“原剧本／说明 → 本区素材 → 视频包”的纵向层次。视频包从左到右按实际包号排列，过长时换行，继续从左到右；分区之间留明显空白。原剧本不覆盖、不复制。没有某层就省略，不造占位节点凑齐。
- 素材按人物、场景、动作／关键保真内容等实际职责排列，只用本次确实需要的现有节点。跨区共享素材保留一份，放在各分区之前的共享素材带；已有共享区位置满意时保留，连到实际使用的视频，不为每包复制一套。节点命名沿用[命名验收](updream-mcp.md#画布资产节点命名与验收)，包名包含包号和真实审核状态。
- 位置依据当前快照的实际节点宽高计算，留出节点上方标题区、水平间距和行间距；长文本、竖图和横图分别按实测尺寸占位。整行按最高节点计算下一行起点，避免卡片、标题相互遮挡或跨入下一片段。不得沿用上个项目的节点ID、固定片段数、固定包数或整套绝对坐标。
- 已满意的区域保持原位；续做默认只为新增／确需整理的节点补位，遵循现有阅读方向和分层。只有用户要求整体整理，或本次区域确实混乱时才重排获准区域。不能移动其他聊天或其他项目的节点；共用一个画布也不扩大范围。
- 连线从真实素材节点指向对应视频包，参考线使用实际工具的 `isReference=true`。先保留现有正确连接，再核对新连接；移动不是重连的理由。普通参考线、专用首尾帧槽、原生引用标签和角色库审核分别验收，不能互相代替。尽量通过位置减少交叉，不为清爽删除有效连线。

## 确定性规划工具

`scripts/canvas_layout.py` 只读文件、输出方案／检查报告，不连接浏览器或移动节点。跨项目可复用，运行前由当前项目真实剧本与素材映射生成 `spec.json`，不得从演示ID或上次聊天猜测。其最小结构如下（数字仅示意，必须换成真实ID）：

```json
{
  "projectId": "当前真实项目ID",
  "groups": [
    {"id": "片段A", "script_ids": [101], "asset_ids": [102], "video_ids": [103, 104]},
    {"id": "片段B", "script_ids": [105], "asset_ids": [102], "video_ids": [106]}
  ],
  "expected_reference_pairs": [
    {"fromNodeId": 102, "toNodeId": 103},
    {"fromNodeId": 102, "toNodeId": 104},
    {"fromNodeId": 102, "toNodeId": 106}
  ]
}
```

`groups` 和 `video_ids` 的数组顺序就是已核对的片段与包号顺序。空层可以省略；仅新增节点时只把这些节点列入各层，已满意旧节点留在快照里作为不可移动障碍。`asset_ids` 可跨区重复登记，工具只规划一次共享节点；其他角色不能重复。`expected_reference_pairs` 填当前待验视频的全部实际参考配对，未提供时只检查布局和旧连线保留，不称素材绑定验收通过。

快照采用当前原生 `canvas_getSnapshot` 的完整 `data`（或完整成功回执），包含 `projectId/nodes/connections/truncated=false`，每个节点有 `id/type/name/position{x,y}/size{width,height}`。分页必须先合并全部节点与连线，确认无遗漏后才标完整；没有真实尺寸时先只读取得，不编默认尺寸。前后快照用同一接口和相同 `includeEdits` 设置。

```text
python "<skill-dir>/scripts/canvas_layout.py" plan before.json spec.json --output layout-plan.json
python "<skill-dir>/scripts/canvas_layout.py" check after.json spec.json --plan layout-plan.json --output layout-check.json
```

规划器按真实尺寸计算标题留白、行距和分区，默认一行最多5个、间距80、标题区40、区距160画布单位；这些是可调整的排版起点，不是画面尺寸或跨项目绝对坐标。Python接口 `make_plan` 可调整这些参数。为保留其他节点，默认在未纳入整理范围的节点下方另开区域；若导致新增节点远离原区，应沿用已有布局就近补位并人工检查，而不是为采用工具输出牺牲可读性。改过方案仍以该最终方案执行读回检查，不能用另一套坐标的报告代替。

## 写入、恢复与验收

1. **记录基线。** 核对当前项目和可写范围；保存完整快照、分区顺序、节点身份／职责和必要参考配对。创建或连接完成后重新取基线，排版阶段只移动节点。沿用[平台路线](updream-mcp.md)，原生接口可用时按实时schema操作，不要求安装额外扩展或改走桌面控制。
2. **形成方案。** 先算位置再移动，只包含获准节点。可用上述规划器，已有满意布局优先按实际结构补位。移动批次大小按当前schema限制；不重命名、不改提示词、不改组归属来代替位置整理。若要用平台分组能力，须另核其副作用和可编辑范围，视觉分区本身不要求新建分组节点。
3. **核对真实结果。** 每批检查逐项回执；部分成功或未知结果先重新读当前坐标，只补未到目标位置的项，不重放整批、不重建节点。协作冲突时不覆盖他人改动。读回失败只记录未核，不称完成。
4. **结构验收。** 全量读回后运行 `check`，退出0只表示 `structure_verified_visual_pending`；1为检查不通过，2为输入缺失／无效。检查目标位置、标题安全区重叠、范围外节点原位、原节点／内容／生成状态保留、旧连线保留、登记参考配对真实存在。工具不验证全文提示词、原生槽位和音画质量；全文仍按[prompts](prompts.md#提示词正文交付检查)单独逐字比对。发现内容或尺寸被并发修改时核实后重取基线／规划，不改基线来掩盖误改。
5. **视觉验收。** 在获准的浏览器页面查看总览和至少一个正常阅读比例的分区／提示词面板：片段界限清楚，包号顺序可循，标题与卡片不遮挡，无明显跨区堆叠；参考线可辨，必要时分区查看而非把全图缩到不可读。截图记录总览及必要细节。禁止桌面控制时只用获准的浏览器截图／公开页面能力；没有可用视觉入口则标 `visual_unverified`，不能让用户自己点来替代已授权的自动工作，也不能把结构检查冒称视觉通过。
6. **交付证据。** 保存实际projectId、范围内nodeId、方案、逐项回执、读回坐标、参考配对、结构报告、视觉检查结论及截图、未核项。只有结构和视觉都验证才称“节点排版已验收”；仅部分通过就分项报告。排版完成不代表视频已生成或可提交，保留用户“先不要生成”的限制。

这些规则适用于不同项目、任意片段数和包数；不把某次成功的数量、坐标、史料、年龄设定或素材清单升格成通用模板。
