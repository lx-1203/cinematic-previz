# 首帧与视频生成适配

连续有声短片的发声覆盖、实际成片偏差与多参考分工，另见 [ai-video-continuity.md](ai-video-continuity.md)。使用 Updream 时先读 [updream-mcp.md](updream-mcp.md)；本地图片先读[快速上传](updream-upload.md)；虚拟角色库、原站确认和未覆盖参数再读 [updream-ui.md](updream-ui.md)。插件只操作已注册的 canvas/gen/materials 能力，不能把本地文件路径当作已上传素材，也不能虚构音频、角色库或首尾帧参数。

## 视觉参数如何传给生成工具

先按 [visual-style.md](visual-style.md) 确定无姓名的视觉方案。提示词不使用导演、摄影师或工作室姓名；用媒介/材质、构图、色调、物体配色、光影和运动的可见描述传达。继承同一视觉方案版本，每镜写本镜落实与允许变化，不堆叠相互冲突的风格词。

首帧表达主体大小、层次、材质、初始配色与既有光源；视频表达动作、摄影机、焦点与光区变化。慢门拖影、抽帧、变速或特定帧率须先核实模型/后期能力，不因提示词写了术语就声称实现。风格板、色号、主辅方案占比都是设计参考，不是API硬锁定参数；负向字段仅在实际支持时使用。

已有选中素材决定连续接点的实际色调、光向和身份状态。风格要求不能覆盖真实尾帧职责；continue 仍原样用上一选中片段尾帧。工具缺少控制能力时记录限制并用兼容参考或后期方案，不虚构字段。

## 表演包的实际适配

含角色动作/对白时用 [performance-compiler.md](performance-compiler.md) 编译，再把逐拍变化传入本镜提示。表演拍不等于切镜或生成片段，不按4秒/8秒的通用阈值硬拆。若必须拆段，每段只写剩余动作和该段原文，对应自然停顿；不能把整镜动作和整句台词复制到每段。当前首帧、身份和真实尾帧规则仍优先。

制作包总是附针对性负向约束，但只有实际支持的模型才使用负向字段；其他路线用正向保留状态和验收项传达。原生音频未知/不支持时保留独立对白、配音与口型计划，不能把“用户要求说话”当成工具支持。原文台词可含情绪词，不为动作黑名单改写原句；OS/画外声不强制出镜人物同步动嘴。文字检查通过后仍需完整回放和逐句试听。

## 白模预演与正式首帧分开

默认先按 [first-frame-previz.md](first-frame-previz.md) 使用内置生图交付逐镜首帧白模，审查构图与开镜状态。环境灰白、主角身份色只是预演标记；进入正式首帧时明确它只提供构图/布局，正式材质、服装和配色来自角色资产与视觉方案。无Blender时可直接生图预演，不能将它称为实测三维。continue已有真实尾帧时原样沿用，不为统一预演画风重画。

## 生图输入的职责

实际查看本地图片后，再按当前工具参数附上图片。绝不能只把文件路径写进提示词当作图片已经传入。宿主提供内置 `image_gen` 时优先使用，无需另外索要 API key；其他宿主使用其实际可用的生图能力，未连接时交付图片提示与素材映射，不静默切换到收费 CLI/API。

| 模式 | 构图来源 | 状态来源 | 外观来源 |
|---|---|---|---|
| 首镜/独立镜头 | 已选首帧构图预演，或对应Blender摄影机图 | 剧本与已确认场景 | 固定角色/场景参考 |
| reangle | 新机位构图预演/白模图 | 前镜真实尾帧、末段动作 | 固定参考持续参与 |
| continue | 直接复用前段尾帧 | 前段尾帧和末段运动 | 尾帧已包含，不重新生图 |
| reset | 新场景机位图 | 新时间/空间设定 | 延续所需身份与画风 |

工具支持本地引用路径时用真实路径参数；支持最近对话图片时使用最少但覆盖全部目标的图片数。遵守当前工具说明，不同时使用互斥引用方式。生成后把最终选图复制到当前项目并保存版本，不能只留在全局生图输出目录。

构图和身份参考是引导，不是像素或几何锁定保证。必须实际查看生成图，检查脸、服装、道具、手别、画面占比、地平线、遮挡和新机位。多格分镜表仅供制作审阅，普通图生视频的主输入应是单幅干净画面。

## 大量画面文字：先做中间关键帧

当系统面板、公告、表格等含大量必须读准的画面文字，且文字需要随 AI 画面生成时，必须先生成并校对中间关键帧，再进入后续视频生成。对白长不等于画面文字多；字幕或信息卡已确定后期排版时，保留无字画面，不额外强制生成带字帧。政策科普默认仍按 [policy-explainer.md](policy-explainer.md) 后期加字，用户明确要求画内生成文字时才走本分支。（2026-10-21，用户明确补充的制作要求；不是某模型已验证的文字保真能力。）

1. 保存逐字原文，明确文字出现的节拍、分行、层级、位置、字号和读卡时间，不自行改写数字、单位、限定词或正文。文字过密时先调整分卡与节奏，不靠缩小到不可读来塞满一屏。
2. 选取文字完整、清楚呈现的代表性时刻生成单幅中间关键帧，沿用该镜角色、场景和构图；它是文字与排版的静态基准，不必位于时长正中，也不是已生成视频的真实中间帧或尾帧。
3. 实际查看图片，与原文逐字核对，检查错字、漏字、重复、数字与标点、分行、遮挡及目标画幅下的可读性。识字工具只能辅助；有误先修图或用确定性文字排版合成基准帧，复查通过后才能进入下一步，不能只补一句“文字必须正确”就提交视频。
4. 将已校对选图及其版本、对应原文、镜号和时刻职责记入现有制作清单。先核实平台支持哪些输入，再用兼容的中间关键帧、普通参考、首尾帧或拆段路线传递基准；没有中间帧字段时不能虚构参数或声称时间点已锁定。参考图片也不保证视频逐字保真；无兼容输入时保留基准并说明限制，提供后期文字层或调整镜头的替代方案，不擅自覆盖用户指定路线。
5. 同机位 continue 仍使用上一已选片段的真实尾帧作为起点；文字中间关键帧只能按实际能力作额外参考，不能替换续接首帧或冒充真实尾帧。输入互斥时按已核实能力调整路线，保留原接点约束。
6. 生成后检查文字出现、变化、停留和退场的画面，并完整回放有字区间，核对逐字内容、排版、漂移、变形和闪烁。静态基准通过不等于成片文字通过；发现问题先记录并修复，沿用既有重试次数、预算和授权边界。

## 先探测视频能力

从已连接工具的当前 schema 或官方文档记录下表；无法确认用 `null`，不能猜成 `true`。只有在准备实际调用时才需要在线核对，能力缓存注明模型 ID 与日期。

| 能力 | 决定 |
|---|---|
| 单首帧 image-to-video | 能否以已选首帧驱动片段 |
| 首尾双帧 | 能否提供计划终态；支持才写对应字段 |
| 参考视频及其参考用途 | Blender 片段可否传递运动/布局 |
| 扩展/续写 | 是否能读取前片的运动历史 |
| 最大/可选时长、画幅、分辨率、帧率 | 逻辑镜头如何分段与交付 |
| 输入互斥、数量/大小、音频/对白支持 | 如何打包素材与后期声音 |
| 价格、额度、返回任务/下载方式 | 已有授权是否覆盖本次请求及重试 |

没有连接可用视频工具时继续准备镜头、图片、提示、引导片与交接清单，明确 `blocked` 和缺少的能力。不要创建假 job ID，也不要假称已提交。

## 路线选择

**只支持首帧：** 用干净首帧和简洁动作提示。Blender 视频用于人工/视觉比对，不能声称相机路径被硬控制。`continue` 可直接用尾帧续接，接点需要更严格验证。

**支持首尾双帧：** 起点和终点都要符合动作与空间，中间路径仍需检查。目标尾帧是规划输入，生成视频真实尾帧是实际输出，二者不能混用。

**支持参考视频：** 导入生成引导版，明确只继承位置/运动/布局。角色、画风和首帧的职责分开；若模型不支持视频与首帧同时输入，按实际可用路线选择：视频加外观参考，或首帧路线。不能伪装成所有输入都生效。

**仅采用风格板的路线：** 用多角度人物、环境、道具参考传递外观，避免某张图的构图与运动片冲突。它不是所有平台的默认，也不是干净首帧的替代参数；逐模型核对。

**支持原生扩展：** 可利用运动历史；记录扩展来源和实际新增时长。用户要求尾帧续接时，先遵循明确要求，能力更合适的替代路线说明清楚。

## 每镜完整提示词必须入表

专业分镜默认直接展示当前可复制的逐镜提示词，不能只附文件路径或只给SH040等单镜示范。按镜号/片段号、提示类型、版本与状态，列完整正文和输入参考职责。为可读性可拆成白模/正式首帧表、视频/声音/负向表，或逐镜键值表；必要信息都在脚本中，不让用户另找长篇附件。

白模提示传构图与起态，正式首帧提示传材质/角色/配色，视频提示传动态进程；不能混成一个通用词段。负向约束无专用字段时保留为制作侧约束，声音不支持原生时保留独立计划。无需某阶段、原稿无对白或continue不重画起帧时，写明“不适用/无对白/直接复用实际尾帧”及原因，不为填表新增台词、重画起点或扩展收费任务。

完整正文不使用省略号、抽象标签、未填变量或“同前镜”；各镜已知的角色、空间、画幅和连续性约束应能随本条提示一起复制。正式身份资产、视频模型或工具能力尚未取得时，表中明确缺项，给模型无关的规划正文，不伪称已可直接提交；参考图用实际附件传入。

已生成预演的原始调用提示按选中图片版本展示，注明生成/编辑以及本次输入参考；修订提示必须附其编辑目标。后来整理的全量重建版另标新版本/未执行，不把它冒充生成当前图片的原词。实际执行文本、当前规划文本及弃用历史分开，不能改写旧调用记录。

长镜头分片段时，在镜头级完整设计之外逐段展开真实剩余动作和当前状态。依赖上游实际尾帧而尚未取得的片段标待上游，不能伪造起态或用同一段完整提示重复表演。提示词表与分镜、图片/片段及原文对白做逐ID、逐版本核对；是否已提交或生成以实际记录为准。

## 每片段提示的内容

每片段明确主动作、主摄影机意图及终态。有叙事必要的连续复合运镜按阶段写清路径与触发，不把多个独立镜头或互相矛盾的运镜当作一次运动。时间分段只用于确有阶段的动作；复杂多人交互按可控性适配，环境运动服务剧情。

`首帧已确定的状态 → 此段继续发生的可见动作 → 摄影机行为 → 此段终态 → 需要保留的身份/空间约束 → 针对实际风险的限制`

同机位续接的下一段不要重复“走进房间”等已完成动作。接正在发生的动作时写其剩余部分；摄像机到达中途而非轨迹起点。画外台词、声音与字幕只有工具支持才放在生成请求，其余由剪辑阶段处理。


把导演稿翻译成模型能看见的变化：从哪个构图开始，在哪个动作或声音触发后怎样移动/停留，焦点落在哪里，光源来自何处、人物如何经过明暗，最后停在哪个构图。保留起幅→揭示点→落幅的因果；导演术语可以保留，但须配可观察描述。复杂连续运动先设计完整路径，再按已核实能力拆段，不静默把每镜都改成慢推。

首帧负责可见构图、初始姿态与光线基线；视频提示负责动态进程。读 [lighting.md](lighting.md)核对光源和阴影连续性。焦距、光比、曝光和秒点在提示词中是设计要求，不因写了数值就称为硬控制或已验证效果。

## 检查、修复和交付

- 生成前：首帧正确、动作可行、能力与参数成立、授权范围清楚。
- 单段后：观看完整片段，并看首中尾和接触帧；确认动作真的发生，而非仅摄像机漂移。
- 接点后：前尾/后首并排，加前后各一小段正常速度回放；静态图相似不证明速度或动作连续。
- 整场后：镜头目的、节奏、视线、空间与声音关系可读；风格/材质、色调、主辅与强调色、肤色和光向保持所选方案，逐镜变化有剧情依据。

脸/服装问题优先回首帧或原始参考；路径和接触问题回白模；片段边界动作重置回全局时序/动作描述；工具不支持的控制回路线选择。每次修改一个主要变量，记录实际结果。在已有授权内可针对性重试两轮，仍不成立则改变镜头方案或明确阻塞。

最终交付可编辑 `.blend`、选中图片/片段、逻辑镜头合成、最终剪辑、制作清单与未验证项，按用户范围缩减。开源 skill 不意味着底层生成服务免费，也不意味着已连接某厂商账户。
