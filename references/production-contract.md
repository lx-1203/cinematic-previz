# 项目记录与可执行示例

## 最小项目结构

在用户指定项目目录内保存；未指定时新建任务目录，保留用户现有文件。文件采用 `SH010/SG01_v01` 这类稳定 ID 和版本。别用“最新文件”自动替代已选版本。

```text
project/
  production.json
  direction/       导演分镜、空间与角色设定
  blender/         可编辑工程、场景脚本和机位图
  previs/          导演预演与逐镜首帧白模图（可放frames子目录）
  guides/          无标注的生成引导片
  frames/          选中首帧、关键帧和固定参考
  clips/           各生成片段及明确的 selected 版本
  handoffs/        真实尾帧、提取凭据、交接检查
  edit/            逻辑镜头合成、声音与最终视频
```

`production.json` 不是第三方 API 请求体。只创建当前任务需要的记录，不为每个小任务批量生成空文件。

需要给既有项目分类、建可见入口、归档或回收恢复时，读取 [项目目录整理](project-organization.md)（模块 `organization`）。下方工程结构与面向用户的分类入口可以并存，不强制搬移正在生产的目录，也不建立第二份相互竞争的选版登记。

## 人物与阶段记录

沿用现有制作登记，以下概念可映射为既有字段，不另建竞争登记或强制改写旧结构：

| 记录 | 必要关系 |
| --- | --- |
| 人物身份 | 稳定 `person_id`、姓名／剧情称谓、C00 等旧资产 ID 或别名、身份依据及其图注／名单／排位位置；未具名者不冒认。 |
| 阶段资产 | 稳定 `variant_id` 关联唯一 person_id，区分剧情时期、年龄阶段和衣装；文件修订另记 version。保存使用镜号、目标时期／阶段与依据，未知精确年龄为 null 或待核。 |
| 双参考与推演 | 图1、图2各自的实际文件／素材 ID、版本、指纹、来源和裁取区域；原照与 AI 派生链、源参考阶段→目标阶段、推演部位、年代依据、模板正文外的授权覆盖项及保持的身份线索、授权指令证据与适用范围。 |
| 选图与目录 | 各阶段当前选中资产及状态、真实路径和 SHA256；同人当前图区分来源图与被替代文件版本，保存旧路径到现路径。目录计划、已复制、已移动与引用已更新分别记录。 |
| 逐镜使用 | shot_id／segment_id → person_id＋variant_id＋asset_id／version；同镜多个时期分别记录职责。改版只将受该阶段影响的首帧／视频等依赖标 stale。 |

生年和图像日期不足以算出确定年龄时保留时期与阶段的不确定性；AI 上色不构成原始颜色证据。只有实际文件、审图和映射均有证据时才把阶段资产标为选中可用，合格旧资产按既有授权复用；修改规则或建立登记本身不代表资产补齐或迁移完成。

## 场景与道具的叙事状态

人物用 person_id＋variant_id 区分阶段，场景与道具同理：同一个空间、同一件器物在故事里跨时间重复出现时，沿用同一个资产 ID，把差异记成带说明的版本，不新建平行条目，否则会出现两套互不相干的外观。

- **道具**：完好的剑→崩口的剑→缠了布条的剑，是同一件道具的三个状态。写清每个状态对应哪些镜号、变化由什么事件触发、可见差别在哪（缺口位置、锈斑、血迹范围、缠布颜色）。
- **场景**：同一处空间在白天、入夜、起火后、雨季时，主光方向、色温、可用光源、地面湿度与破损程度都会变。默认版本写一次，其余版本用一两句写清差异（门板是否关闭、灯笼是否点亮、血迹是否还在），并标各自的适用镜号。
- **变化必须有可见触发**：谁弄坏的、哪一场烧的、从哪一镜开始下雨。找不到触发的差异属于错误，先不改；确需改就先改剧本或写明理由。
- 资产 ID 稳定、状态另立版本号并写触发镜号；下游首帧与视频按依赖标 stale，不因登记了状态就宣告已同步。

## 兼容示例：显式单镜与6秒限制下的接力

这是**显式单镜兼容规划示例，非新项目默认路线**，没有附带真实图片或视频。仅用于用户已明确选择独立单镜且目标工具存在所述限制的情况；新计划先朗读核算、每15秒一多镜大段，不能复制下面的旧任务拆法作为默认。假设现场核实目标工具最多 6 秒且支持首帧输入，设计 12 秒长镜头，再切一个成片保留3秒的特写（实际生成4秒）。真实任务根据当前模型重新核实时长。

场景：女子右手持钥匙靠近门，男友在她后方走廊。门向室内开启，门框、锁和两人关系在白模中固定。

| ID | 全局镜头时间 | 任务 | 结束状态 | 接下一段 |
|---|---|---|---|---|
| SH010/SG01 | 0–6 秒 | 同一跟拍镜头，女子走近门 | 到门前，右手抬起但钥匙未接触锁 | continue |
| SH010/SG02 | 6–12 秒 | 保持跟拍机位和运动趋势，完成插钥匙 | 钥匙插入、尚未转动，门仍关闭 | reangle |
| SH020/SG01 | 成片0–3秒／生成0–4秒 | 切门外锁具特写，看清开锁 | 右手转动钥匙，开锁完成 | cut 或按后续剧情选择 |

执行顺序：

1. 完成导演分镜，安排空间和动作；在 Blender 同一 SH010 曲线上规划 0–12 秒。
2. 生成 SH010/SG01，选中真实视频和剪辑范围后提取尾帧，记录检查。
3. 以该 PNG **原样**作为 SH010/SG02 首帧；接着抬手接近并插入钥匙，不重新走到门前。引导片使用 SH010 曲线 6–12 秒。
4. 提取 SG02 的实际尾帧，确认钥匙、手别、门和男友位置。若实际未插入，先处理该差异。
5. 把此状态冻结在 Blender，摄影机移到**门外**锁具特写，检查朝向和遮挡。首帧保持“插入、未转动”。
6. 生图时实际附上 SG02 尾帧、新机位白模、人物/手部服装及道具参考；生成 SH020 首帧，检查通过后生成转动钥匙的镜头。
7. SH010 两段拼成同一长镜头，检查接点运动速度；SH010→SH020 是有意切机位，检查动作接点和声音。

门内反打是另一种设计：关门时门板会遮挡人物，可拍门内锁具/门板并以画外声音传递动作，或等门打开后再看到人物。不要把门外图简单翻转成门内视角。
