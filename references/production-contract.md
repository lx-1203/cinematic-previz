# 项目记录与可执行示例

## 最小项目结构

在用户指定项目目录内保存；未指定时新建任务目录，保留用户现有文件。文件采用 `SH010_SG01_v01` 这类稳定 ID 和版本。别用“最新文件”自动替代已选版本。

```text
project/
  production.json
  direction/       导演分镜、空间与角色设定
  blender/         可编辑工程、场景脚本和机位图
  previs/          导演预演与逐镜首帧白模图（可放frames子目录）
  guides/          无标注的生成引导片
  frames/          选中首帧、关键帧和固定参考
  clips/           各生成片段及明确的 selected 版本
  handoffs/        真实尾帧、提取凭据、交接检查
  edit/            逻辑镜头合成、声音与最终视频
```

`production.json` 不是第三方 API 请求体。只创建当前任务需要的记录，不为每个小任务批量生成空文件。

需要给既有项目分类、建可见入口、归档或回收恢复时，读取 [项目目录整理](project-organization.md)（模块 `organization`）。下方工程结构与面向用户的分类入口可以并存，不强制搬移正在生产的目录，也不建立第二份相互竞争的选版登记。

## 记录字段

制作阶段与审核：沿用[十步主流程](workflow.md#制作阶段与审核顺序)，保存当前阶段、文档及含首帧Excel的路径/版本/指纹、用户实际通过或修改指令的证据与适用镜号；未获用户通过写待审核，不以Agent自审或已生成文件替代。改源只更新受影响状态，已通过同版不重复索要。仅草稿/不提交、只首帧等范围独立记录，审核通过不自动解除。

Excel视频词来源：每镜记录工作簿版本/SHA256、核心主表的权威单元格/列、shot_id/segment_id、当前词版本与全文/指纹、实际写入全文、读回比对和对应节点ID。当前词只维护这一源，附表/平台必要展示同步并核对；JSON仅作已核Excel的逐字导出缓存。获授权改词先改Excel，保留差异、依据及新版本；不以新词覆盖历史调用。不完整读回保持未核对，节点存在不代表原词相同。

主表交接包：按 [核心主表规范](director.md#默认交付专业分镜表) 关联必要分镜、当前完整视频词、选中首帧与人物/场景/表情/物品参考的ID、版本、原图指纹和职责；记录图片可导出入口或随包相对路径/授权链接、原图与预览对应。保存计划参考节点ID/复用范围/顺序/依赖及真实平台资源、节点、边ID与状态；尚未创建标明未创建。记录平台/模型版本（可得时）、模式、画幅、时长、分辨率、实际支持且已知的参数、审核版本/范围和缺口。接手者不应只拿到本机绝对路径或无权访问的节点号；实际生成记录仍逐版本保存，不能用当前词回写历史。仅在具备相应审核与输入/能力证据时标最终可执行。

OpenCut交付：记录真实素材、镜号与时间线位置、声音和字幕时窗、工程入口与保存状态、实际字体/填充/描边及导出文件指纹；默认宋体SimSun、白色#FFFFFF、黑边#000000。按实际语音校字幕，不把静音占位、SRT或时间线JSON称成品；实际导出和音画字幕验收分别记录。

项目：标题、画幅、帧率、时长、原始设定引用、工具与实际能力、用户已授权的范围/预算。

预算沿用 [SKILL.md 的视频项目预算规则](../SKILL.md#视频项目预算)。在现有项目记录中保存 `budget.currency=CNY`、`budget.max_cost_per_generated_second`（默认1）、`budget.source`（用户指定或默认）及累计实际费用；只有用户设置时才保存项目总额上限。每次付费任务记录 `cost_check`：原始报价及单位、人民币换算口径与来源、本次人民币费用、生成秒数、元/秒、是否超预算、用户选择和授权状态。未知换算或费用用 `null` 并标记未核实，不填0或判定预算通过；这些是本地制作记录，不作为平台API参数。

视觉方案：沿用现有记录或保存 style_profile 的 ID/版本、媒介与用途、剧情依据和情绪曲线、主风格家族、构图/运动/色调/配色/光影/材质/节奏、硬约束与规划/验证状态。有辅方案时只记录借用的1—2个维度与冲突优先级。来源标为剧情推导、用户明确偏好或已查看素材；不设姓名透镜字段，不为已有剧情重复征求风格选择。逐镜记录所用版本及有依据的局部变化，改版核对依赖。它是本地制作记录，不是模型请求体，不强制新建独立JSON文件。详见 [visual-style.md](visual-style.md)。

逻辑镜头：scene/section/shot ID、叙事任务、信息变化、构图与运动、动作起止、全局时长、角色/道具/空间约束、片段 ID 列表。

逐镜参考映射：人物参考、场景参考、表情参考、物品参考分别记录，可映射为现有记录中的 `references.characters / scenes / expressions / props`，不强制迁移数据结构。每项保存资产ID/职责、实际文件或可访问链接、版本、指纹、来源/专业依据与事实或制作设计性质、使用镜号、实际核验与用户选择状态；无独立参考记空列表及不适用原因。表情资产关联具体角色和镜内情绪，不替代身份图；专业物品另关联正视/展开内容稿与入画版本，二者不可混称。选中图、表格预览、完整提示词及真正传入工具的附件须能追到同一资产版本。只登记参考不写成已入画，用户认可不代替逐字/专业内容核验或成片检查。

人物参考还须关联下方 `person_id`、具体 `variant_id` 和使用阶段；不能只按人物名或 person_id 为所有年代套同一演员板。逐镜所选图片、表格预览、实际附件和可复用节点都须解析到该阶段的同一文件版本。

表情参考的必要性按 [expression-assets.md](expression-assets.md) 从每人开镜事件、神态与可见性判断；无独立表情图要记录具体理由，不能用空数组绕过明确需要的表情控制。选图资产与调用附件分别保留版本/指纹和职责，既有人物、表情参考不能仅登记而未输入。执行前从现有记录及真实拟调用参数导出 [执行检查视图](execution-checks.md)，执行后核对实际输入；导出是可再生快照，不替代Excel和现有选版源，也不能补造未留存的历史调用。

分镜字段按 [导演执行要求](director.md#把运镜写成能执行的画面变化)与[打光语言](lighting.md)补充：场次保存观察立场、视觉递进、光源位置与主次明暗基线；镜头保存起幅/落幅、运动动机与触发、路径和节奏、焦点策略、继承的光线基线与本镜可见效果、切点及验证状态。可映射到现有字段，不强制迁移用户的数据结构；用户阅读的脚本正文也须包含这些设计，不能只存在JSON中。

高级镜头设计：按 [camera-language.md](camera-language.md) 保存本镜类型/组合、剧情触发、起幅/关键揭示/落幅、阶段起止时间、世界路径/朝向/高度/绕行范围、速度意图、焦距与焦点策略、切点和回退。时间变化另记源/输出锚点、实际采样/交付帧率、变速路线和音轨对齐，未知实测数值保留未核实；类型编号是检索信息，不是模型API参数。复合运动沿用同一逻辑镜头，片段间保存相机姿态、速度、焦距、焦点、主体动作相位及真实尾帧。静态图、三维轨迹、实际视频、音画各自记录检查结果，不用一个总通过标记覆盖未验证项。

表演包：按shot_id/版本关联 [表演编译结构](performance-compiler.md)，保留source原意与逐字台词、推断项、可见通道、逐拍触发/主动作ID/线索、语音时段与参数、负向约束、实际能力、片段起终状态。自动报告由脚本重算，语义审读保存判断与依据，视频/口型/声音检查另记；不将自报quality、规划状态或静态计数冒充实际成片证据。

首帧白模预演：按shot_id/script_version关联frame_role=start、source_kind=codex_imagegen_blockout、版本化文件与指纹、原始提示/参考职责、角色身份色映射、实际目视检查及缺陷/未验证项。规划首帧、正式外观首帧与实际视频尾帧分别标记，身份色不改正式配色；字段见 [first-frame-previz.md](first-frame-previz.md)。

提示词记录：按shot_id/segment_id、type、version关联完整正文、实际参考输入及职责、对应图片/视频版本和planned/submitted/generated等真实状态；原始调用文本保留，不被后来改写覆盖。主表权威单元格直接展示当前完整视频正文，生图/资产规划与实际执行证据按职责入附表；必要复用展示从单一当前源同步，不能只链接此记录。编辑词注明输入目标，重建词与实际调用词分开。

生成片段：所属镜头、segment ID、逻辑镜头内时间区间、首帧、引导片、生成路线与实际模型、提示文件、任务状态、视频版本与指纹、实际保留范围、选中版本、检查结果。

转场：按 [transitions.md](transitions.md) 记录transition_id/版本、前后镜号或同镜阶段、叙事联系和时空断点、机制与衔接模式、匹配锚点、实际选片入出点/时间基准和余量、前后完整提示词及参考职责、负向/声音、剪辑/遮罩/白层/屏面合成路线与能力依赖。屏幕揭示另记真实内层媒体/指纹、后续源区间和源到输出时间映射；规划帧与真实输入分开，改源标stale。文本、静态、动态接点、最终合成及音轨分别保存实际结果，未制作不称无缝验收。

转场改版关联受影响的前出/后入素材、Excel权威词、剪辑任务版本及最终输出。只有剪辑变化时不重制合格视频，生成内容变化时才使相应下游失效；旧任务或旧输出的回放不能替当前版结项。按同transition_id保留待素材/待剪辑/待验收/stale及真实结果，delivery校验后仍逐项实际回放，详见 [转场改版与逐项落实](transitions.md#转场改版与逐项落实)。

交接：源 segment/版本/指纹、真实尾帧和提取凭据、`continue/reangle/cut/reset`、状态清单、新机位构图来源、目标首帧与视频、依赖项、检查状态。

所有帧编号说明是 0-based 还是 Blender 1-based，禁止混用。脚本提取工具采用 **0-based 解码显示顺序**；Blender 时间轴通常从 1 起。VFR 源视频的时长/帧号不能只用平均 FPS 换算；统一时间基准时先转码并记录转换来源。

状态机：

`planned → ready → submitted → generated → reviewed → selected`

缺能力/素材为 `blocked`；被改版来源影响为 `stale`。不要通过改标签把缺失或未查看的文件标为通过。

## 人物与阶段记录

沿用现有制作登记，以下概念可映射为既有字段，不另建竞争登记或强制改写旧结构：

| 记录 | 必要关系 |
| --- | --- |
| 人物身份 | 稳定 `person_id`、姓名／剧情称谓、C00 等旧资产 ID 或别名、身份依据及其图注／名单／排位位置；未具名者不冒认。 |
| 阶段资产 | 稳定 `variant_id` 关联唯一 person_id，区分剧情时期、年龄阶段和衣装；文件修订另记 version。保存使用镜号、目标时期／阶段与依据，未知精确年龄为 null 或待核。 |
| 双参考与推演 | 图1、图2各自的实际文件／素材 ID、版本、指纹、来源和裁取区域；原照与 AI 派生链、源参考阶段→目标阶段、推演部位、年代依据、模板正文外的授权覆盖项及保持的身份线索、授权指令证据与适用范围。 |
| 选图与目录 | 各阶段当前选中资产及状态、真实路径和 SHA256；同人当前图区分来源图与被替代文件版本，保存旧路径到现路径。目录计划、已复制、已移动与引用已更新分别记录。 |
| 逐镜使用 | shot_id／segment_id → person_id＋variant_id＋asset_id／version；同镜多个时期分别记录职责。改版只将受该阶段影响的首帧／视频等依赖标 stale。 |

生年和图像日期不足以算出确定年龄时保留时期与阶段的不确定性；AI 上色不构成原始颜色证据。只有实际文件、审图和映射均有证据时才把阶段资产标为选中可用，合格旧资产按既有授权复用；修改规则或建立登记本身不代表资产补齐或迁移完成。

## 场景与道具的叙事状态

人物用 person_id＋variant_id 区分阶段，场景与道具同理：同一个空间、同一件器物在故事里跨时间重复出现时，沿用同一个资产 ID，把差异记成带说明的版本，不新建平行条目，否则会出现两套互不相干的外观。

- **道具**：完好的剑→崩口的剑→缠了布条的剑，是同一件道具的三个状态。写清每个状态对应哪些镜号、变化由什么事件触发、可见差别在哪（缺口位置、锈斑、血迹范围、缠布颜色）。
- **场景**：同一处空间在白天、入夜、起火后、雨季时，主光方向、色温、可用光源、地面湿度与破损程度都会变。默认版本写一次，其余版本用一两句写清差异（门板是否关闭、灯笼是否点亮、血迹是否还在），并标各自的适用镜号。
- **变化必须有可见触发**：谁弄坏的、哪一场烧的、从哪一镜开始下雨。找不到触发的差异属于错误，先不改；确需改就先改剧本或写明理由。
- 资产 ID 稳定、状态另立版本号并写触发镜号；下游首帧与视频按依赖标 stale，不因登记了状态就宣告已同步。

## 示例：先长镜头续接，再切机位

这是**规划示例**，没有附带真实图片或视频。假设现场核实目标工具最多 6 秒且支持首帧输入，设计 12 秒长镜头，再切一个 3 秒特写。真实任务根据当前模型重新核实时长。

场景：女子右手持钥匙靠近门，男友在她后方走廊。门向室内开启，门框、锁和两人关系在白模中固定。

| ID | 全局镜头时间 | 任务 | 结束状态 | 接下一段 |
|---|---|---|---|---|
| SH010/SG01 | 0–6 秒 | 同一跟拍镜头，女子走近门 | 到门前，右手抬起但钥匙未接触锁 | continue |
| SH010/SG02 | 6–12 秒 | 保持跟拍机位和运动趋势，完成插钥匙 | 钥匙插入、尚未转动，门仍关闭 | reangle |
| SH020/SG01 | 0–3 秒 | 切门外锁具特写，看清开锁 | 右手转动钥匙，开锁完成 | cut 或按后续剧情选择 |

执行顺序：

1. 完成导演分镜，安排空间和动作；在 Blender 同一 SH010 曲线上规划 0–12 秒。
2. 生成 SH010/SG01，选中真实视频和剪辑范围后提取尾帧，记录检查。
3. 以该 PNG **原样**作为 SH010/SG02 首帧；接着抬手接近并插入钥匙，不重新走到门前。引导片使用 SH010 曲线 6–12 秒。
4. 提取 SG02 的实际尾帧，确认钥匙、手别、门和男友位置。若实际未插入，先处理该差异。
5. 把此状态冻结在 Blender，摄影机移到**门外**锁具特写，检查朝向和遮挡。首帧保持“插入、未转动”。
6. 生图时实际附上 SG02 尾帧、新机位白模、人物/手部服装及道具参考；生成 SH020 首帧，检查通过后生成转动钥匙的镜头。
7. SH010 两段拼成同一长镜头，检查接点运动速度；SH010→SH020 是有意切机位，检查动作接点和声音。

门内反打是另一种设计：关门时门板会遮挡人物，可拍门内锁具/门板并以画外声音传递动作，或等门打开后再看到人物。不要把门外图简单翻转成门内视角。

## 项目 JSON 示例

```json
{
  "schema_version": 1,
  "title": "走廊开锁",
  "status": "planned",
  "format": {"aspect": "16:9", "fps": 24},
  "capabilities": {"verified": false, "image_to_video": null, "max_seconds": null, "reference_video": null},
  "shots": [
    {"shot_id": "SH010", "scene_id": "SC01", "section_id": "SEC01", "duration_seconds": 12, "segments": ["SG01", "SG02"], "purpose": "连续跟随至关键线索"},
    {"shot_id": "SH020", "scene_id": "SC01", "section_id": "SEC02", "duration_seconds": 3, "segments": ["SG01"], "purpose": "确认钥匙转动与开锁结果"}
  ],
  "handoffs": [
    {"from": "SH010/SG01", "to": "SH010/SG02", "mode": "continue", "source_video": null, "tail_receipt": null, "next_start": null, "status": "planned"},
    {"from": "SH010/SG02", "to": "SH020/SG01", "mode": "reangle", "source_video": null, "tail_receipt": null, "next_start": null, "status": "planned"}
  ]
}
```

null 表示尚未取得/验证，不是允许把缺项当作 ready。为实际制作补充上一节字段；不要把示例的假设能力写成现场已验证能力。
