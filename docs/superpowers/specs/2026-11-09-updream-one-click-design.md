# Updream Windows 双击安装包

目标：用户自行解压、双击 install.bat，不需要安装 Node/Python、不输入命令或手动导入配对文件；保留浏览器原生的扩展加载确认。开发期间不操控用户桌面、不改现有安装、不提交媒体生成。

方案比较：仅脚本下载依赖体积小但首次联网和环境故障多；扩展商店安装最短但需要独立审核发布；采用自带已校验 Node 与锁定生产依赖的离线 ZIP。Node 和依赖仅在发布构建时下载，最终用户离线可安装。

范围：从保留的完整 Bridge 0.3.0 分享快照恢复独立子目录，发布 Bridge 0.3.1；不把它冒称丢失的 Bridge 0.4/0.6，也不替换技能 0.6 内容。以 origin/main 最新提交建立隔离分支，正常更新现有 GitHub 仓库。

安装数据流：双击 ASCII/CRLF bat → 内置 Node 验证包清单 → 复制到用户 LocalAppData 的稳定目录 → 创建/保留本机配对 → 仅修改已管理的 Codex MCP 表并备份 → 校验服务真实 tools/list → 生成含本机私有配对文件的扩展副本和中文安装引导 → 用户加载此副本后扩展自动读取私有资源并连接。网站内容脚本不接触令牌，私有资源不声明 web_accessible_resources。

重复安装保留密钥和已有配置；未知/未管理的配置拒绝覆盖；旧服务有工作区、在途请求或写操作时拒绝重启。端口已占用且无法认证时只在首次安装选择空闲端口。配对文件、安装状态、备份和依赖缓存均不提交 Git；公开 ZIP 不含配对密钥，发布构建包含逐文件 SHA256 清单及 Node 官方校验值。

验收：配置保留/冲突/损坏/并发保护测试，自动配对和重连测试，真实 MCP 目录验证，隔离临时目录安装及再次安装测试，解压发布 ZIP 后用其自带 Node 运行测试入口（不打开浏览器、不创建真实快捷方式）；包清单与秘密排除核验。浏览器实站加载由用户操作，不能把测试替身的握手称为实站安装成功。

发布：源码提交到现有 main；独立 updream-bridge-v0.3.1 标签触发 Windows 构建与 GitHub Release 资产上传。核对远端 commit、源码文件 SHA256、发布包和本地产物的来源及内容。失败保留成果并报告具体未完成阶段。
